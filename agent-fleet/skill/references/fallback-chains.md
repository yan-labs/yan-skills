# 执行者不可用时的换手

先读调遣令和全局索引。新任务按当前顺位换手，用 `fleet-go relaunch` 保留原 brief 与验收。正在运行的任务继续到明确交接点。遇到网络抖动先查目标，确认可安全重试再同档试一次。

| 信号 | 动作 |
|---|---|
| Codex 额度达到配置阈值或确认耗尽 | 查调遣令及 OpenAI API 入口是否可用，按实际授权换手 |
| 容量不足或并发满 | 依全局路由排队，或用同能力的可用通道 |
| 402 与限流 | 先区分账户额度、模型过载、请求预算和并发限制。额度更新写调遣令，短时限流按通道容量处理 |
| 应用内代理后台失败 | 检查最后的证据和产物。原会话恢复后可用 `SendMessage` 接续 |
| 必需工具不可用 | 换能取得同等证据的通道，否则按实际缺口交回 |

`fleet-go order show` 读取调遣令。额度失败命中机读规则时由 fleet 更新状态，运行在 fleet 之外的通道需手工记录。按 `fleet-go order set --help` 填执行者、状态、期限和抽象原因，实际恢复后可用 `fleet-go order clear`。额度判定查实现中的 `QUOTA_RULES`。

## 应用内代理

需要应用内工具、登录态或 MCP 时，才选择有相应能力的执行者。调用时显式指定模型，保持原授权边界。并发满先等通知或按全局顺位换手。回退后在报告记实际模型和保留的产物。普通执行者不继续派单；授权总管按 brief 分工。

### Fable 与 Astra 分工

Fable 需要应用内工具时用 `executor-fable`。同样的架构决策、方案维护或复杂判断可在工具条件允许时用 `--to gpt --astra` 承接。两档都应写清决定边界、可证伪的验收和后续维护责任。Astra 是否用于复杂实现由全局索引与调遣令决定。续做优先追加修订，以保留已验证的上下文。
