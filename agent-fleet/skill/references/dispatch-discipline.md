# 派单纪律：brief、报告、复核、总管、失败

## Brief
- 自包含：首行 `归类：…；理由：…`（编程路由拿不准就归 Codex）；`REPORT: <绝对路径>`，默认 `~/.agent-reports/<YYYY-MM-DD>/<任务短名>.md`；目标、读写路径、边界、客观验收；多个任务并发写同一处时写 CONFLICT-SCOPE。
- 路径一律写绝对路径；相对路径会按 `--cwd` 解析，找不到时执行者会空转。
- 每句话都问一遍：省掉它会不会让执行者做错、白忙或出事故？会就留下。小事一两句，恢复和迁移类可以写长。事故任务先交代事件经过和有意保留的现状。
- 授权参数和正文保持一致：`--auth local|local-commit|readonly-web|deploy-prod|paid|review` 按需组合；远程操作用 `deploy-prod,readonly-web`；要本地提交选 `local-commit`；仅授权含 `local-commit` 或 `deploy-prod` 且正文明确要求提交时，缺哈希才算缺项，其余单不检查哈希。
- Codex 单写明“自己在本线程顺序完成，不开子代理”（模板已带）；要等子任务回来才能收尾的单，写明负责人自己等到结果。允许开子任务时写明并发上限。
- 需要执行者做授权、续聊这类动作的验收，要在 brief 里点名允许，否则它会停在门禁前。
- 发出前核对：结果、独有信息、边界、回交条件、验收标准。

## 报告
- 开工先写「规则回执」，阶段结果随时落文件。最终回复给报告路径和三行结论；`--review` 只读复核的结论写在最终回复里，由负责人汇入报告。
- 七节完整、回执与 brief 一致才算合格。主线程对照日志核对：交付是否完整、是否逐条达标、过程是否越界、有没有敏感输出。线上只读命令要点名副作用（如 `pm2 ls` 会拉起守护进程）。
- 验收时一并核对文档与记忆同步（brief 模板已要求）：受影响的文档、记忆已删旧写新，没有新旧并存；子代理、Agent 工具派的单 brief 里也要写这一句。
- fleet 状态 done 只代表进程退出：先读报告「结论」和线上真实状态（`git ls-remote`、`gh run`、describe），没做完就 `fleet-go amend --say "续做……"`。
- 报告超过约 150 行，先让 Haiku 按验收答“达标/未达标/证据在哪”，再决定是否细读；日志和 diff 先看摘要或 `head`。

## 独立复核
- maker 和 checker 用不同执行者（另起新任务即可，不必换厂商）。
- 编码：另起一个 Terra 单只读复核，对照 diff 和测试（`--review` 默认走 Terra，brief 写明“只读，不改项目文件”）。文案、简单配置、有明确测试的单点修复可免。
- Gemini 交付的文案，验收前另起 Terra 只读核对事实与遗漏（用户 11-10：Gemini 容易编造）。
- 非编码（调研、报告、采集、建站收尾）：JEV 判达标与边界，置信度低于 0.55 交只读 Terra；文案语气复核可交 Gemini。
- 复核结论追加到报告 `## 复核`。checker 只在自己的 `mktemp -d` 里建删文件，用户真实配置只读。
- 发现明显无关的产物、越界文件、擅自发布、提交或换模型，先如实告诉用户再处理。

## 后台、唤醒与总管
- fleet 一律用 Bash 的 `run_in_background:true` 启动，命令末尾不加 `&`、`nohup`。结束本轮前确认本会话有有效唤醒源（在跑的后台任务），用 `fleet-go status` 核实。
- 派出后主线程不监工：不挂 Monitor、不派监工 agent、不轮询、不看日志。长等待写进 brief，让执行者自己等、自己查。
- 多步链路（maker → checker → 修复 → 下一步）派一个总管：`fleet-go new <名字>-orchestrator --to gpt`（监工类可用 `--luna`）。brief 写清整条链、每步授权（逐条继承用户原话，未授权推送部署的写“只本地提交”）、只读 Terra 复核、修复最多 3 轮、成功与阻塞的判据。总管只在全链完成或必须用户决定时返回一次。
- 收到通知后读报告验收；没有新结论的通知不回复用户。纠偏用 `fleet-go amend --say`；核心验收已过就算过，非本单原因的失败最多再试一次后记偏差。同类跑偏出现第二次，回头改模板或本 Skill。
- 自己能运行的自动化不另建 AI 定时器监工；要建监控，先说清“发现异常谁来动手、结论给谁看”。用户明说“盯一下”才挂监工，平静时不返回。

## 时间盒补充
- 换班时如果下游任务正在写共享树，先等它结束或明确交给新总管，不同时留两个写入者。
- 快照缺失时，新总管从 brief、报告和各仓 git 状态重建。

## 失败与重派
- 网络抖动同档重试一次。402、额度用尽、登录失效、模型拒绝：`fleet-go relaunch <名字> --to <执行者> [--tier ..]` 按工具链重派同一 brief。
- 用户点名 Sol 时报 “Selected model is at capacity”：同档重试一次，仍不行改 Terra。
- 裸 tool-call 控制 token、空结果、verdict `suspect`/`fail` 都算失败，退出码 0 也一样。
- 非 GPT 档重派保留归类和规则句，报告写换档原因，产物交不同厂商复核。

## 时间关键步骤（切流、停机、降档、发版窗口）
- 主触发放在 Mac Mini：执行者在进程内等到时刻再动手，或在 Mini 上用 launchd 一次性任务启动 `fleet-go new`。MacBook 会话里的 CronCreate 只在会话空闲时触发，只能当备份。
- 脚本和 brief 第一步写 `<报告目录>/<名字>.lock`，1 小时内已存在就退出；到点后约 5 分钟核实际动作回执，缺了立即手动派。
- 睡前接力写清每一步的主触发、备份和核验时刻。

## 已知坑
- zsh 里 `echo ======` 会被当成 `=` 展开报 “not found”；分隔线加引号：`echo '====='`。

## /design 画布
- 同一站点同一画布，各主题在 `canvas.json` 的 `pages` 里建独立 page，board/note 用 `page` 归属。
- 第一页 UI library 定组件、颜色、圆角、按钮、间距、图标；其他页引用它，先改 library 再改页面。视觉风格经用户确认后，建该画布独立的 Design System（`/design` 的 Design System 类型），后续需求先改它再改页面。
- `fleet sonnet`（难的 `fleet opus`）在本地写 `.dc.html`、CSS、`canvas.json`；`executor-haiku` 用 Artifact 工具按目录逐页上传，同一画布上传串行，并发改动前先重读最新 `canvas.json` 合并。
- brief 不推送时避免“推送出去的…”等歧义用语，写“将来公开的历史”；选 `--auth local-commit` 并写明“本单不推送”。
