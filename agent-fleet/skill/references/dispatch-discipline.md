## Brief

像交代给刚接手的同事：用大白话讲清背景、想要的结果、允许范围、缺口怎么处理、怎么算完；做法留给执行者。一单只围绕一个目标，多个方向拆成多单。

- **自包含**：首行 `归类：…；理由：…`（编程路由拿不准就归 Codex），`REPORT: <绝对路径>`（默认 `~/.agent-reports/<YYYY-MM-DD>/<任务短名>.md`），目标、读写路径、边界、客观验收。这些样板 `fleet-go new` 会自动补，正文只写任务独有的部分。多个任务并发写同一处时写 CONFLICT-SCOPE。
- **每句话问一遍**：省掉它会不会让执行者做错、白忙或出事故？会就留下。小事一两句，恢复和迁移类可以写长；事故任务先交代事件经过和有意保留的现状。
- **路径先核实**：读写清单里的路径用 `ls` 或 `test -e` 确认；新文件确认上级目录存在并写成「新建，路径为……」。一律绝对路径，相对路径会按 `--cwd` 解析，找不到时执行者会空转。
- **每条限制先确认现实能满足**（只读账号、全程只读、只用某工具）：做不到或拿不准，就把替代护栏一起写上。例：没有只读账号，就写“用现有账号 + 只读事务 + 超时”。
- **验收写结果并给备用办法**（例：深色测量受限时测浅色），列出产物清单和每件的篇幅上限、做到哪就停。需要执行者做授权、续聊这类动作的验收，在 brief 里点名允许，否则它会停在门禁前。
- **授权与正文一致**：见 [fleet-go 派单参考 · 授权与动作](fleet-go.md#授权与动作)。不推送的单选 `local-commit` 并写明“本单不推送”；避免“推送出去的…”这类歧义说法，写“将来公开的历史”。
- **子任务**：Codex 单自己在本线程顺序完成，不开子代理（模板已带）。允许开子任务时写明并发上限；要等子任务回来才能收尾的，写明负责人自己等到结果。
- **共用的东西由主线程提供**：两单以上都要的外部状态、环境准备、公共信息，按全局 §3 由主线程取一次再 `fleet say` 分发，brief 里写明“做到需要它时交回或等通知”。
- **取证类**（打开外站、查 DNS/RDAP、批量读页面）写明重试与降级：打开失败同 URL 重开或刷新，间隔约 5 秒，最多 5 次；单项仍取不到记「无法验证」并继续。站点整体不可达、验证码、限流、登录墙时报告缺口，继续其余工作。
- **涉及数据、备份、数据库、云资源**写明执行位置：“备份、恢复、DB 工具及所需软件在 AWS 上（跳板机、ECS 任务、容器）执行，本机只保存行数和摘要，沿用已有软件。”来由：Codex 曾在用户 Mac 上自行 `brew install` 数据库；验收时在执行者日志里检索安装命令的执行位置。
- **浏览器步骤**统一 `opencli browser <会话名>`；改文件的短命令单加 `--expect-changes`。
- **行动范围句**由 fleet 自动加在每个 brief 前（逐字文本在 `src/scope.mjs` 的 `SCOPE_LOCK`）：围绕一个目标做必要改动，小障碍选保守办法继续并记「偏差」，授权有缺口时先完成授权内部分。brief 只需补充本任务的具体边界。
- 发出前核对五样：结果、独有信息、边界、回交条件、验收标准。

## 报告与验收

- 执行者开工先写「规则回执」，阶段结果随时落文件；最终回复给报告路径和三行结论。`--review` 单的结论写在最终回复里，由负责人汇入报告。
- 七节完整、回执与 brief 一致才算合格。主线程对照日志核对：交付是否完整、是否逐条达标、过程是否越界、有没有敏感输出。线上只读命令也要点名副作用（如 `pm2 ls` 会拉起守护进程）。
- fleet 状态 done 只代表进程退出：先读报告「结论」和线上真实状态（`git ls-remote`、`gh run`、describe）。没做完就 `fleet-go amend <名> --say "续做……"` 列出没做的验收项。
- 核对文档与记忆同步（验收样板已要求）：受影响的文档、记忆已删旧写新，没有新旧并存。用 Agent 工具派的单，brief 里也写这一句。
- 报告超过约 150 行，先让 Haiku 按验收答“达标/未达标/证据在哪”，再决定是否细读；日志和 diff 先看摘要或 `head`。
- 发现越界文件、方向改变、替代品冒充交付、擅自发布、提交或换模型，先如实告诉用户再处理。

## 独立复核

分档与必修项标注规则见全局 §4.3，不在这里复述。落到 fleet：

- maker 和 checker 用不同执行者：另起新任务即可，不必换厂商。
- 编码：另起只读 Terra 单对照 diff 和测试，`fleet-go new <名> --to gpt --review --auth review --for <被复核任务名>`。brief 只给代码、diff 和验收条件，不给 maker 的结论。
- Gemini 交付的文案：验收前另起只读 Terra 核对事实与遗漏。
- 非编码（调研、报告、采集、建站收尾）：JEV 判达标与边界，置信度低于 0.55 交只读 Terra；文案语气复核可交 Gemini。
- 复核结论追加到报告 `## 复核`，末尾带机读尾注（见[账本](ledger.md#复核尾注)）。checker 只在自己的 `mktemp -d` 里建删文件，用户真实配置只读。
- 必修项用 `fleet-go amend <maker 名> --say` 交回 maker 修；标了「派单可预防：是」的，另走下面的派单复盘。

## 派单复盘（每单不顺都做）

目的是让同一类问题不在下一单重演。用户 2026-11-16：“不能盲目地去加一条记忆或者加一条规则，因为规则可能会冲突，记忆可能会打架，所以必须是整理和优化。”

**触发**：verdict 不是 `ok`；要 amend 续做；复核有必修项；启动或预检被拦（缺路径、授权与动作不符、lint）；执行者因 brief 写法停下或越界。

1. **先救这单**：`fleet-go amend <名> --say` 列出缺口让它续做。Terra 交回 partial 不改派 Sol（全局 §2「路由」）。
2. **归因一句，选一类**：

   | 类 | 成因 | 怎么办 |
   |---|---|---|
   | A | 入口或信息缺：文件、凭据位置、前置报告没给 | 派单可预防，必须改规则 |
   | B | 限制做不到或写太死（如“只读账号”现实不存在） | 同上 |
   | C | 授权与动作不匹配 | 同上 |
   | D | 环境没备好：Mini 路径、checkpoint、Skill 版本 | 同上 |
   | E | 验收没写清，或没写停点 | 同上 |
   | F | 执行者自身：brief 已写清仍提前收尾或越界 | 先查模板有没有对应句，有就不加；同类第二次再改模板或 lint |
   | G | 外部真实阻塞 | 不改规则，只写报告 |

3. **选落点**：只关这个项目 → 项目派单手册（`.rankup/infra/13-dispatch-kit.md`，没有就 `.rankup/dispatch.md`）；跨项目 → 本 Skill；能用程序查的（路径存在、授权与动作、必带引用）→ 改 `fleet-go lint` 或预检，不写成文字。
4. **整理而不是追加**：先 grep 落点里同主题的条目。有就改写那条（合并新现象、更新写法与日期）；被推翻的删；互相矛盾的按用户最新原话留一条；没有才新增。每条写成「现象一句 → 派单时怎么写（可复制的一句）→ 来源（日期、任务名）」。一条规则只存一处，别处放指针。落点文件超过约 300 行或某节超过约 40 行时，同一轮合并同类、删过期。
5. **当场生效**：本单续做的 amend 就用新写法；派下一单前按项目手册的「派单前必读速查」自查。

**复核反馈**：checker 每条必修项按全局 §4.3 标「现实会发生 / 仅极端条件」和「派单可预防：是/否」（复核样板已带）。“是”的走上面第 2–4 步。

## 后台、唤醒与总管

- 派出后主线程不监工：不挂 Monitor、不派监工 agent、不轮询、不看日志；在跑任务由半小时巡检照看（[巡检与主会话交班](patrol-and-handoff.md)）。长等待写进 brief，让执行者自己等、自己查。结束本轮前用 `fleet-go status` 确认本会话有有效唤醒源。
- 多步链路（maker → checker → 修复 → 下一步）派一个总管：`fleet-go new <名>-orchestrator --to gpt --sol`（纯监工类可用 `--luna`）。brief 写清整条链、每步授权（逐条继承用户原话，未授权推送部署的写“只本地提交”）、只读 Terra 复核、修复最多 3 轮、成功与阻塞的判据。总管只在全链完成或必须用户决定时返回一次。
- 收到通知后读报告验收；没有新结论的通知不回复用户。核心验收已过就算过；非本单原因的失败最多再试一次后记偏差。
- 自己能运行的自动化不另建 AI 定时器监工；要建监控，先说清“发现异常谁来动手、结论给谁看”。用户明说“盯一下”才挂监工，平静时不返回。

## 失败与重派

- 网络抖动同档重试一次。402、额度用尽、登录失效、模型拒绝：`fleet-go relaunch <名> --to <执行者> [--tier …]` 按[工具链](fallback-chains.md)沿用同一 brief 重派。
- 用户点名 Sol 时报 `Selected model is at capacity`：同档重试一次，仍不行改 Terra。
- 裸 tool-call 控制 token、空结果、verdict `suspect`/`fail` 都算失败，退出码 0 也一样。
- 换到非 GPT 档重派时保留归类和规则句，报告写换档原因，产物交不同厂商复核。

## 时间关键步骤

切流、停机、降档、发版窗口这类到点必须发生的动作：

- 主触发放在 Mac Mini：执行者在进程内等到时刻再动手，或在 Mini 上用 launchd 一次性任务启动 `fleet-go new`。MacBook 会话里的 CronCreate 只在会话空闲时触发，只能当备份。
- 脚本和 brief 第一步写 `<报告目录>/<名>.lock`，1 小时内已存在就退出；到点后约 5 分钟核实际动作回执，缺了立即手动派。
- 睡前接力写清每一步的主触发、备份和核验时刻。

## /design 画布

- 同一站点同一画布，各主题在 `canvas.json` 的 `pages` 里建独立 page，board/note 用 `page` 归属。
- 第一页 UI library 定组件、颜色、圆角、按钮、间距、图标；其他页引用它，先改 library 再改页面。视觉风格经用户确认后，建该画布独立的 Design System（`/design` 的 Design System 类型），后续需求先改它再改页面。
- 分工：`fleet-go new … --to claude --tier sonnet`（难的用 opus）在本地写 `.dc.html`、CSS、`canvas.json`，fleet 通道没有 Artifact 上传权限；上传由 Agent 工具的 `executor-haiku` 用 Artifact 工具按目录逐页发布。同一画布的上传一次只派一个，并发改动前先重读最新 `canvas.json` 合并。
