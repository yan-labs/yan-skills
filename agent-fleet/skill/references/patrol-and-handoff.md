## 巡检子单做什么

每次定时触发，主会话先看有没有后台任务在跑：没有就 CronList 找到这条巡检并 CronDelete；有就派一个 Terra 巡检子单（`--to gpt --on mini`，`run_in_background`），brief 用本机 `~/.agent-fleet/patrol-brief.md`，提示里写明本会话负责的任务名。巡检用会话内 Cron，不用独立定时任务。

巡检子单：

- 只看、只指挥本会话派出的 run；已结束的 run 不发指令。
- 检查日志与产物变化，纠正卡住、空转、循环或偏题的任务；判断无望时终止。
- Terra 单 30 分钟无新产物或两轮续做无进展，改派 Sol（规则见全局 §2「路由」）。
- 记录追加到当天的 `fleet-patrol.md`。
- 最终回复第一段写「需要主会话处理」，列出自己用 fleet 命令解决不了的事：缺授权、需要改派执行者或档位、多单争用同一资源、需要用户配合、已终止的单是否重派。每条写任务名、现象和建议，没有就写「无」。

## 主会话怎么处理巡检结论

完成通知回到派单的主会话。主会话必须读「需要主会话处理」并逐条处理：补授权、改派、调整顺序、找用户或重派。只看巡检记录不算处理。

## 换班（执行者跑太久）

- 触发：单个 run 约 2 小时没有新产物，或累计运行约 5 小时。日志、报告或进度文件仍在增长的算正常推进，不按时长换班；有进度文件的长任务以进度文件的更新时间判断是否卡住。
- 做法：让执行者写 checkpoint 并结束本轮（brief 里的时间盒块已要求写 `~/.agent-reports/<日期>/<名>.checkpoint.md`），再 `fleet-go relaunch <名>` 换新 agent 读 checkpoint 接着做。
- 下游任务正在写共享树时，先等它结束或明确交给新总管，不同时留两个写入者。
- checkpoint 缺失时，新执行者从 brief、报告和各仓库 git 状态重建。
- 思维准则随 brief 走（[派单纪律](dispatch-discipline.md#思维准则与场景透镜)）：`relaunch` / `amend` 重派时，缺「思维准则」的旧 brief 会被自动补上，新执行者的预期和原执行者一致；checkpoint 里不用重复。

## 主会话交班：何时交

主会话不等用户提醒，自己按时交班，也不等手上所有单都结束（用户 2026-11-13）。满足任一条就交：

- 本会话已被压缩（compact）过一次；
- 连续派单值守约 4 小时；
- 一个里程碑或一批单验收完；
- 用户提到额度、token 烧得快，或直接说“交接/交班”。

开始派后台单时，和半小时巡检一起挂一条交班检查；交班时连同巡检一起删，新会话重挂：

```text
CronCreate(cron="13 * * * *", prompt="【交班检查】按 agent-fleet「巡检与主会话交班」判断是否该交班：满足任一条就立即执行交班步骤；否则不动。")
```

## 主会话交班：六步

1. **纠偏、更新项目记录，再写交接文件。** 用户 2026-11-15：“交班的时候必须要更新文档，并且对自己做一次纠错或自省，然后再告诉下一个交班的同事，让他保持专注的方向继续推进。”
   - 纠偏：重读项目 `.rankup` 里这条线的大目标和计划（plan、worklist 对应行），把本棒派过和在跑的单逐个对一遍：是在推进计划里的某一项，还是半路冒出来的细枝末节（临时修环境、调研时顺带发现的、该排到后面阶段的、新方案上线后会被重写的）。后一类停掉或挪到计划里对应的阶段，不交给下一棒。
   - 更新：把本棒合入的、在跑的、改了的决定写进 worklist 对应行和计划（计划有唯一维护人的交给维护人改）。没更新不算交班完成。
   - 交接文件 `~/.agent-reports/<日期>/session-handoff.md`：开头两节是「大目标」（用户原话一句）和「本棒自省」（偏在哪、怎么纠的、下一棒只推进哪几项）；然后是用户方针与授权原话、在跑和排队的 run 及 runId、会话内定时原文、子代理单和报告路径、已决定不做的事、待拍板的事、新坑。
   - 接班会话派新单前先核对这单对应计划里的哪一项，对不上就不派。
   - 交接文件里加一行「派单思维准则照 agent-fleet 执行」，并列出本棒用过的场景透镜（代码考古、认知成本、PR 变慢、返工复盘）；接班会话先读 SKILL.md 开头那一节，`fleet-go new` 自动带，Agent 工具派的单手贴（[派单纪律](dispatch-discipline.md#思维准则与场景透镜)）。
2. **处理定时和等待进程。** 会话内定时（巡检、交班检查、一次性定时）随会话消失，原文已写进交接文件，先不删，等第 6 步新会话确认后再删。停掉纯等待的 `fleet wait` 后台命令；`fleet-go relaunch --after` 排队命令和 caffeinate 这类承载任务的进程不停。
3. **开接班会话：普通会话，不用定时器。** 用户 2026-11-14：“就正常用正常对话吧……让他自己自动去开一个，然后自己归档就好了，就不走这个定时器了。”定时器起的会话不能置顶，也收不到持久任务完成通知。
   - 有 `start_session`：以项目主克隆根目录为 `cwd`、`use_worktree: false` 开普通会话（派单机任何会话都不建 worktree）。提示词：「接 <项目> 运维主线程：读交接文件 <路径>，重建会话内定时、改绑持久任务通知、置顶自己并改名「<项目> 运维主线程（第 N 棒）」，再 SendMessage 通知旧会话 <local_ id> 删定时并归档」。
   - 没有（定时、巡检等非人工轮次）：用 `spawn_task` 出一张同样提示词的接班卡片等用户点开，旧会话期间照常值守。
4. **处理还没回来的 Agent 子代理（executor-*）。**
   - 正在写代码、发布等有实际产出的：让它做完，结论用 SendMessage 转给新会话。
   - 只在等的（等定时点、等迁移、等 CI）：SendMessage 让它收尾——停掉自己的后台等待；确认真正干活的进程已脱钩（Mini 上父进程为 1，或在集群、服务端跑），否则先改成脱钩；在报告末尾写「交接 checkpoint」（做到哪、怎么查状态、下一步命令与判据、回滚）；worklist 标“由新主会话接续”；然后结束。旧会话把 checkpoint 路径转给新会话，由新会话挂定时到点派执行者。
5. **持久任务通知改绑（接班必做）。** App 持久任务跑完只通知最后一次设 `notifyOnCompletion` 的会话。新会话 `list_scheduled_tasks`，对本项目所有 enabled 的和今天跑过的任务逐个 `update_scheduled_task(notifyOnCompletion: true)`。新建持久任务的提示词要求结果写进报告和 `.rankup/worklist.md` 对应行，通知漏了也能读回。
6. **旧会话自动归档，不问用户。** 用户 2026-11-13：“你应该自动归档啊。”收到新会话“定时已重建”的确认之前，旧会话照常值守、定时不删。确认后：删掉自己全部定时；确认没有未转交的子代理、没有挂在本会话的承载进程；用 `mcp__ccd_session_mgmt__detach_session` 把接班会话移到顶层，再用 `mcp__ccd_session_mgmt__archive_session` 归档自己（先 ToolSearch 加载）。旧会话若在 `.claude/worktrees/<名>`，归档后确认无未提交改动、无其他会话使用，再清理该 worktree 和 `claude/<名>` 本地分支。最后只回复一行说明已归档；不为了等某个凌晨定时点把旧会话留着。新会话不重派已转交的单。

## 已知坑

- 子代理等待时会开很多「Wait until …」后台进程，它们挂在本会话，会话归档就跟着停。等待一律改成 checkpoint 加新会话定时。
- run 结束或交班时，它启动的子进程会被一起停掉（曾连带杀掉后台复制进程）。要跨棒存活的长进程从一开始就和 run 脱钩启动，PID 和续传方法写进 checkpoint，交班前确认。
- 要在凌晨执行的变更，优先写成 Mini 上脱钩的常驻脚本（自带门禁和自动回滚），子代理不用在线等，读日志验收。
- 同一时段两个生产变更错开至少 15 分钟，出了问题才分得清原因。
- 子代理再派子代理会被 hook 拦下；它需要复核时交回主会话安排，不绕到别的通道。
