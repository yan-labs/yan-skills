# 监督、巡检与换班

启动即登记 runId 和 owner。会话巡检按全局约定挂一次，负责核对漏登、处理异常及换班，空清单时撤销。

## 三种场景

| 场景 | Brief 必需输入 | 结束条件 |
|---|---|---|
| `snapshot-patrol` 快照巡检 | runId、时间窗、每个 run 的读取入口 | 每个 run 都有证据和一个决定，仍在跑也可交付 |
| `wait-terminal` 等终态 | 精确对象、版本或提交、成功/失败/取消条件、终态后的回读 | 唤醒后逐项回读，二次超时按外部受阻交回 |
| `watch-window` 窗口值守 | 起止时间、采样间隔、指标、owner、取数命令和阈值 | 窗口结束且每个间隔都有事实行，异常附裁定 |

用 `fleet watch patrol` 读在途任务事实。窗口值守由脚本定时取数，触阈或状态变化再裁定。快照巡检只做一轮，每单选不动、插话纠正、要求快照、停止或交主会话，执行干预须有授权。

## 席位监听与信箱

Claude 的 `SessionStart` 和 `UserPromptSubmit` hook 可调用 `fleet watch hook`：从 hook 输入取得会话 ID 和目录，回传本席在途、未读及确认命令；子任务不会领取指挥席。SessionStart 有 `CLAUDE_ENV_FILE` 时将会话 ID 写入 `FLEET_DISPATCH_SESSION`；Codex 未设置该变量时使用 `CODEX_THREAD_ID`。

席位通常为「仓库#派单会话」；接班用原 `FLEET_LINE` 沿用席位，新会话成为当前席位代。`fleet watch status --seat <席位>` 查看在途及未读；`fleet watch listen --seat <席位> --session <当前会话ID>` 每 15 秒检查未读变化，席位换代时退出，`--once` 只检查一次。

Mini 信箱位于 `~/.agent-fleet/watch/mailbox.sqlite3`。监督器对账补录有归属的在途任务和 24 小时内的未登记终态，未读保留到确认；hook 单次最多显示 20 条，确认后可见后续。信箱不可达时 hook 报未同步及缓存时间。

处理事件后执行 `fleet watch ack <eventId> --seat <席位> --session <当前会话ID>`；只有当前席位代可确认。显式 `fleet wait <runId>` 仍可取结果，并对取到的事件记回执。

## Park 等待

先做独立验收，把本单触发的外部条件交给 runner。向 `fleet park` 传 `--until` 条件、`--item` 验收项、`--timeout` 时限、`--say` 唤醒首动作。Actions 条件使用 `gh-run:<GitHub Actions URL>@<完整 SHA>`。长命令用 `fleet bg` 得到 job 条件。runner 负责等待和重新取得名额。首次超时核对精确对象和最后状态后再等一窗，二次超时标「受阻」及「等外部」。派单方供数直接交回。用 `activeMs`、`waitMs`、`pollCount` 分读活跃、等待和探测次数。

## 打转与巡检间隔

以验收状态、根因证据、有效产物差异和有区分力的测试识别进展。排除排队、park 和已登记的慢构建。警讯包括十分钟内同目标重复命令或脱敏输出三次、活跃三十分钟无进展、连续高消耗零产物、二十分钟内反复改回原内容，以及模型长 sleep 或频繁查未变条件。缺计量时标未知。

1. 同一信号先插话一次，明确验收项、最后证据和可验证的下一条路径。
2. 确认送达后再过十分钟仍打转，先取快照，核安全中断，再由同档接续。涉及在途外部写入或安全状态不明时交主会话。
3. 两轮续做无进展，或达到全局停滞规则且纠正无效，带快照和最后证据交主会话裁定。

新单首窗、发布生产单和异常单按十分钟检查，稳定单按三十分钟。异常恢复后连续两个密巡窗口有进展才转疏，生产操作全程密巡。park 只核等待条件健康。合批复核首审、证据不足、范围变化和异常任务，健康且未变的裁定标时间后复用。

## 逐单六问

1. 哪项证据支持当前根因？
2. 动作对应哪个原始验收，解决的是真问题吗？
3. 方法、范围与授权及 owner 一致吗？有多余改动吗？
4. 继续或打断影响哪些操作及共享资源？
5. 有更便宜且可验证的备用路径吗？
6. 哪条证据能推翻当前判断？

输入使用事实表和最近有效进展后的脱敏日志摘要，每单最多 12 条事件。每单一行，格式为「run｜根因与真问题｜方法及范围｜多余改动｜影响｜替代路径｜反证｜建议动作与 owner」。证据不足先补一个有区分力的观测。用 `fleet watch patrol --record-reviews` 从标准输入写回按 runId 键控的 JSON，值含 `evidence`、`verdict`、`inputTokens`。

## 交班

派单方达到全局交班条件时核真实在途 runId，先纠偏并更新项目记录。执行者达到 brief 的换班条件时写权威快照，包含原始验收、已完成和证据、未完成及 owner、授权裁定、第一步。支持时用 `fleet handoff` 登记接力。需要跨轮存活的进程核脱钩和续查方法。

接班会话恢复在途任务的完成通知和定时职责，核对计划、运行对象、授权和下一步。接班确认后旧会话撤销自己的定时、核实无未转交进程，再按平台能力归档和清理自己的工作区。
