# 派单记忆

| 层 | 位置 | 放什么 |
|---|---|---|
| 源码层 | Skill 源码 | 跨用户、机器和项目通用的方法、命令、脚本和样板 |
| 全局层 | `~/.agent-fleet/` | 跨项目的个人约定、调遣令、全局场景和本机配置 |
| 项目层 | `<项目>/.agent-fleet/` | 项目总则、场景、入口和验收证据约定 |

先用 `fleet-go context` 读索引、调遣令和场景，再按索引读所需细节。优先级见 [入口](../SKILL.md#上下文)。项目首次有内容时再建目录。

| 内容 | 维护方式 |
|---|---|
| 规则 | 可复用的做法和判据。修改既有条目，索引常驻、细节按需读 |
| 状态 | 当前调度、计划或接力位置。覆盖旧值，注明期限；可从环境直接取到的值现场重读 |
| 记录 | 报告、账本、失败经过、原话和授权证据。追加保存，按保留期清理，按需引用 |

规则才算记忆。全局索引写跨项目路由，项目总则写该项目每单须知，`lessons.md` 写可复用经验。凭据只在本机受控配置中使用，项目 `.env` 须被 Git 忽略。

## 写入与蒸馏

一条一行，最多两行。格式为「祈使句规则。适用：条件。因为：一句抽象理由。〔验证：检查方法〕〔例：去标识示例〕〔来源：记录指针〕」。规则和适用条件必填，理由建议保留，后三项各至多一条。区分实测、经验与猜测，猜测留在待验证记录。

1. 判断是否会复发。一次性的经过留记录。
2. 判断代码、测试或场景能否拦住。能就优先修机制。
3. 在目标层搜同主题条目。有就修改那条的适用范围或理由，否则新增。
4. 超限时在同一轮合并或删除旧条目。

场景是规则的最高形态。能变成场景默认值、必填入口或具名验收项的规则优先放进场景，让实际 brief 自动继承。

## 触发与整理

写入时点见[验收与收尾](../SKILL.md#验收与收尾)的五项。调遣令更新属于状态修改。运行 `fleet-go doctor`、出现超限或重复警告、主会话交班时整理，对照记录验证条目。

- 同一规则在两个以上项目成立，可晋升全局层。与用户和机器无关的规则经复核后可晋升源码层。
- 仅一个项目使用的条目下沉。由代码或场景覆盖、理由失效的条目删除。90 天未使用的场景先核实再删。
- 索引和项目总则各 ≤60 行，一般规则文件 ≤150 行，每项目场景 ≤20 个。相同规则只维护一处。

## Lint

`fleet-go doctor` 报告五类规则警告：长引号或带日期的用户出处、日期密度过高、超行数、近似重复、绝对措辞缺适用条件。另查规则中的疑似密钥、项目 `.env` 跟踪风险、过期调遣令和安装漂移。按报告定位修改。
