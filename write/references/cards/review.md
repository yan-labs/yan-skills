# 核对卡 · review 执行者

适用：别人写好的站内页面、营销文案或文章稿，交给你只读核对后改到能交。你和写稿的人不是同一个执行者。

## 输入

- 待核稿件（文件或字段文本）
- 写稿时用的输入：页面清单、产品事实、来源清单
- 写稿用的卡（如 `site-page.md`）

## 必读

1. `../executor.md`
2. 写稿用的那张卡，按它的完成标志核
3. 站内页面再读 `../official/google-content.md` 的「必读精简版」，涉及的小节读全文

## 逐条核

每条答「通过 / 不通过 / 证据位置」，不通过的直接改稿并列出改动。

1. **事实对输入。** 每个功能、数字、价格、日期、引语、评价都能指回输入里的一条；对不上的删掉或记缺口。限定词、数字归属、引用归因按 check.md「改写，守住事实」逐条对。
2. **官方层逐条。** 站内页面按 official/google-content.md 的精简版逐条核，涉及的小节按全文核；不通过的写编号。
3. **体检。** 自己重跑 `check.py`（站内页加 `--meta`，JSON 加 `--json`），硬禁为 0；档位和提示项回到上下文判断，不只看分数。
4. **页间重复。** 批量页抽两页互换目标短语，仍读得通就记「模板换词」；title、description 不重复。
5. **承诺对正文。** title、description、H1 说的事正文里都有。
6. **不加料。** 稿件没有超出卡要的范围；改稿长度不超过原稿 1.25 倍。

## 交回

改后的稿件、逐条结论（一行一条）、改动清单、缺口清单。不打总分。
