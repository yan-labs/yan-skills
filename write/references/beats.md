# 按拍推进：叙事、科普、故事

适用：读者需要被带着走的文章，叙事、科普、故事。面对完全不懂的读者做科普，一律用这个。输入同样是一堆素材，成文写进另一个文件，素材文件只读。

## 流程

1. **定前提。** 先和用户谈定读者进门时已经懂的概念。其余都要由某一拍先落地，后面的拍才能用。
2. **起 2 到 3 个起拍。** 都取自素材，是进入文章的不同入口。每个只准借已落地的概念，并注明它落地什么新概念。先给用户看，不写进文件。用户选定后，预告这个选择会解锁哪些后续的拍。
3. **只写选定的那一拍**进文章文件，然后停。一拍可以是一句话，也可以是几段。
4. **重读文件**，再给 2 到 3 个候选下一拍，是从文章现在的位置可以转向的不同方向。每个都必须能从当前已落地的集合到达，并注明各自落地什么。
5. 重复第 3、4 步，直到文章自然收束。

做的时候你自己扮演两个角色，起候选的人和选的人。用户在场就让用户选，用户明确说你来定，就按「读者此刻最需要什么」自己选，并用一句话交代理由。

## 落地

一拍要先有它所需的概念已落地，才能用它。单位是概念，不是词，一拍可以借一个读者没有的想法，哪怕没有术语。概念有名字时，落地就是想法和名字一起交代。

每一拍做两件事。它要求某些概念已经落地，也落地一些新概念。随手维护一张已落地清单，每写完一拍就更新。

可达性决定了推进方式。候选拍只有在它要求的概念都已落地时才可达。选了一个落地概念 X 的拍，就解锁所有在等 X 的拍。

当一个诱人的拍要求了没人落地的概念，修法有两个。前面插一个落地拍，或者把这个概念升为前提。

## 什么是一拍

一拍是旅程中的一个动作，布置场景、落下一个论点、提出一个问题、插一句旁白、转一个角度，然后停在下一拍能接上的位置。

大小按需要定。

- 一句话，如果动作只有这么多，比如「然后三周什么都没发生。」
- 一小段，如果动作要铺垫。
- 几段，如果这一拍是独立的小场景、论证或例子。

如果一拍要五段加三个小标题，它其实是两拍粘在一起，拆开。

## 取料与收束

素材是采石场。可以转述、拆分、重组或引用。文章在素材用完之前就可以结束，旅程走完才算完，素材剩下是正常的。

## 写的节奏

- 一次只追加一拍，不往前写。
- 每次写之前重读文件，绝对保留用户的改动。
- 用户大改了前面某一拍，后面要跟着变。
- 用户说「这一拍重写」或「回去换一个第三拍」，原地编辑，其余不动。

写完进入 SKILL.md 阶段三和四。
