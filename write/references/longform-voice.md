# 长文笔法与稿子太完美时的诊断

适用：公众号类长文、随笔、评论，要写出一个真人在认真聊一件事的声音。事实类、科普、商务文体不要照搬口语化部分，按 SKILL.md 阶段四的保守规则处理。

## 先判选题

动笔前过一遍三问，至少占两项才值得写。

- 有趣吗，标题和开头能让人好奇点开
- 有信息量吗，读完能学到新东西
- 能戳中情绪吗，读者会想「我也这么想」

只占一项要和用户重新商量角度，一项都没有就劝放弃。素材不够就先问用户要，比如想讲哪几个点、有没有自己的经历、哪里特别想吐槽。

## 分工

这一步守住事实和经历的边界。

- 你可以做的有找证据和佐证、给类比候选、按用户已定的角度扩写、补学科背景、调整结构。
- 必须来自用户的有第一手观察和真实经历、核心创意角度、真实的情绪、从一个数据想到具体的人。没有就向用户要，不替作者编经历，不编场景。写不出真实细节时，宁可承认「这个我自己没试过」。

## 先判原型，再定写法重心

| 原型 | 核心 | 写法重心 |
|---|---|---|
| 调查实验 | 我替你去做了这件事 | 过程叙事，每一步带真实反应，发现层层递进 |
| 产品体验 | 跟我一起玩 | 场景演示，真实感受，和同类自然对比 |
| 现象解读 | 你注意到了吗，背后是什么 | 观察、好奇、研究、知识掉落，再往上一层 |
| 工具分享 | 我发现一个好东西 | 先讲个人故事，再引出工具，再展示效果 |
| 方法论 | 把压箱底的掏出来 | 每节落一个今天能做的动作，坦白学习成本和失败点 |

## 笔法

- **节奏是推进系统。** 主线是绳子，每次偏出去一点，让读者喘口气、看个案例，再用一句话拉回主线。这种扣主线句要高频，一句就够。偏得太远再硬拽，读者要花脑力顺逻辑，读不下去。
- **句长有长有短。** 一句话自成一段用来压重点，全篇不滥用，关键处用。疑问句可以当刹车和转向。
- **知识顺手掏出来。** 聊到那里正好想起来，不写成「下面科普一下」。
- **从亲历切入。** 用自己的经历连接公共话题，不写「这给我们的启示是」。有好恶可以直说，姿态是被打动了，不是居高临下点评。
- **先站到对方处境里。** 讲观点前，把对方的处境具体写出来，承认它合理，再给自己的看法。
- **层层剥开。** 现象、表面解释、更深的追问、核心判断，让读者参与推理。
- **回环。** 前面埋的意象或细节，后面要以变体再次出现。埋了就得响。
- **开头从具体的当下事件切入。** 不用宏大叙事，不用「在当今时代」。第一句要让人想问「然后呢」。
- **多项对比逐一展示。** 每个带一句具体点评，弱的放前，最出人意料的放最后，让情绪逐级升上去。
- **案例要有独立的看点。** 评测和推荐类至少有一个让人想说「还能这样」的案例，按挑战、思路、过程、结果的顺序讲。用真人案例要讲完整的弧，只截取对论点有利的部分，懂行的读者会觉得偷换概念。
- **方法论文章的每一节读完要有动作。** 结构是观点、支撑、具体怎么做、坦白学习曲线和失败点。开头可以先承认自己也不确定，不摆教人的姿态。
- **用具体名字。** 写「Claude Code」「Seedance 2.0」，不写「某个 AI 工具」。
- **字数和格式。** 长文常见 4000 到 8000 字。段落短，常常一句成段。不加小标题，用口语转场衔接。只有「N 条心得」这种本身分条目的文章才用数字编号。

## 结构骨架

开头从具体事件起，迅速建立情绪。背景用聊天式科普铺开。核心内容分几个板块，每个板块有一个明确观点，至少一个具体场景、人物或对话，一处自己的视角，和一句扣主线的话。收尾选一种，引用别人一句话、短句留白、让读者去做一件事、回到开头的意象但视角已变。不写章末小结，也不为了升华硬拉到哲学和历史。

## 稿子太完美时的诊断

AI 稿的问题常常是写得太光滑太均匀，没有一处是作者自己也没想通的。check.py 抓不到这些，通读时逐条对：

| 症状 | 处理 |
|---|---|
| 堵死所有反驳，读者没提的异议也答了 | 只留真被人问过的那一条 |
| 知识全部倒出，术语数据堆满 | 留一个真用来想事情的，其余删 |
| 同一个让步模板反复走，每一轮结构相同 | 第二遍起换说法或跳过 |
| 给概念起名字的仪式用了两次以上 | 只留一个真精准的名字 |
| 情绪曲线光滑，没有一处没想通 | 把没想通的地方留着，别修圆 |
| 替读者编一句蠢话再纠正 | 读者真说过才写，否则删 |
| 全篇毫无犹豫，每句都笃定 | 真不确定的地方写出来 |
| 精确到不真实的细节，如「1.7 秒」 | 没量过就用嘴上会说的词 |
| 个人经历只为论点服务，一点多余细节都没有 | 保留与论点无关但记得清楚的那部分 |
| 前面说不能被简化，结尾给一个简化版协议 | 删结尾的协议或承认矛盾 |
| 每段都收一句金句 | 只让最重要的一句出头。短视频口播每段一句是体裁要求，不算 |
| 同义词刻意替换，一段里换好几个词说同一件事 | 词准就重复用 |
| 自己没有的朋友故事，「有个朋友……」 | 补上名字和差错，补不出就换成自己的经历 |
| 结尾「你值得」式祝福 | 删最后一段，看文章是否已经结束 |
| 实操问题被升维到「本质上」 | 删那句比前文大一号的命题 |
| 用身体感受替代论证，「身体知道答案」 | 讲不下去就直说讲不下去 |

误伤要避开。学术和法律文体穷尽反驳是规范，短视频口播的开头钩子是体裁。拿不准体裁时按保守处理。

和 write 的规则冲突时以 write 为准。口语化不等于可以破例，翻案句式、破折号、提示性冒号、矫饰比喻照旧不用。
