# 挖素材：先放开，不定结构

适用：用户只有一个模糊想法，或一个话题，还没有稿子。这一步只做探索，不排大纲、不分章节、不写成文。结构留到 shape.md 或 beats.md。

## 做法

1. 问清用户想写什么、给谁看，然后用追问把素材逼出来。一次只问一个问题，追问要具体，比如「这件事最让你意外的是哪一刻」「你当时怎么想的」「有没有一个只有你见过的细节」。
2. 从用户说的第一句话起就记片段，包括最初那条提示。
3. 片段追加写进同一个 markdown 文件。用户没给路径就问一次存哪，之后沿用。
4. 文件第一次写入时，顶部只放一个 H1 工作标题，不加元数据、目录、日期。
5. 每次写入前先从磁盘重读文件，保留用户中途的改动，只追加，不覆盖。用户说「删掉上一条」「改利落点」「合并这两条」，按字面执行。
6. 追加时顺口说一句「记下了」，不弹确认，不打断谈话。

## 什么算片段

片段是任何可能活到终稿里的文字，作者看得懂就行，不必自洽，也不必给术语下定义。标准是这段文字本身好不好，不看它是不是完整论证。

- 一句想用但还不知道放哪的利落话
- 一个论断加一行理由
- 一个小场景，一件发生过的事，一段代码，一个类比
- 一个没想完的念头，「X 有点像 Y，回头想」
- 一句引语，一段对话，一句听来的话
- 一组凭感觉放在一起的观察
- 一句抱怨，一句坦白，一个包袱

## leading word

最值钱的片段是 leading word，一个能撑起整篇的比喻或造词，像「曳光弹」「战争迷雾」那样一个词点名一整个模式。它定下后面的结构、转场和标题。

谈话里同一个意思反复绕的时候，逼用户给它起个名字。候选词至少给两三个，让用户挑或自己改。一篇只留一个，后面每一节都要能挂回它。挂不回去的比喻按矫饰处理，删掉。

## 文件格式

片段之间用单独一行 `---` 隔开。片段内部不加标题、标签，顺序就是加入顺序。引语单独成片段，用 `>` 引用，下面可以跟用户的反应。一组相关观察可以放成一个列表片段。

## 收工

用户说够了，或同一批意思开始重复，就停止追问，提示可以进入 shape.md 或 beats.md。素材文件在后两步里是只读的输入。
