# 站内文案：营销页与页型

适用：写或改网站上的页面文字，官网首页、落地页、定价页、功能页、关于页，要说服并促成动作；任何语言都适用。做哪些页、每页的目标词与意图由 rankup 给；带来源的文章读 sourced-article.md；站内 blog、模型页、对比文走 blog Skill。

## 一、营销文案

### 动笔前问清

页面类型和读者要做的唯一一个动作、理想客户是谁和他们的顾虑与说法、卖的是什么和相对替代品的差别、能拿出什么证据（数字、评价、案例）、流量从哪来。项目里有现成的产品营销上下文文件就先读，只问缺的。

### 原则

- 清楚比聪明重要，二选一时选清楚。读者要解码才懂，就已经丢了。
- 写好处，不只写功能。功能是它做什么，好处是对客户意味着什么。
- 具体胜过笼统。「每周报表从 4 小时缩到 15 分钟」强于「节省时间」。
- 用客户自己的话，来自评价、访谈、客服记录。
- 每一节只推进一个论点，页面顺着逻辑往下走。
- 诚实。编造数据和好评会毁掉信任，也有法律风险。证据没有就不写，不替用户虚构。

### 风格

主动不被动，简单不复杂，具体不空泛，自信不打折扣。去掉「几乎」「非常」「真正」这类削弱语，用结果代替副词，删感叹号，删没有内容的营销词（赋能、一站式、全方位、创新）。中文文案同样适用。

### 页面结构

首屏有四样。标题，只讲最重要的一件事，说清核心价值，具体胜过泛泛。副标题，扩写并加具体度，一两句。主按钮，写动词加得到什么，比如「开始免费试用」强于「提交」。支撑的视觉。

标题常用结构有 6 种。

- 达成结果而不用忍受痛点
- 类别加受众，如「给创业团队用的轻量 CRM」
- 再也不用遇到某种糟事
- 直接点出痛点的提问
- 数字加人群加结果
- 一个类别加唯一差别，如「会自己更新的 CRM」

首屏按「现在的不适、更好的图景、通往它的路」组织。写完标题做一次检验，能不能补成一句「现在你可以……」，补不出来说明标题没讲到结果。

主体常见区块和用意如下。

| 区块 | 用意 |
|---|---|
| 社会证明 | 建立可信度，认得出的客户比多更重要，数字、评分、简短评价 |
| 问题 | 比读者说得更准，让他认出自己，暗示不解决的代价 |
| 方案与好处 | 3 到 5 个，不写 10 个，每个有标题、说明和证据 |
| 怎么用 | 3 到 4 步，降低复杂感，每步写动作和结果 |
| 异议处理 | 常见问题、对比、保证 |
| 收尾 | 重述价值，重复主按钮，降低风险（保证、试用） |

按钮文案避免提交、了解更多、点击这里、开始，用具体的，如「获取完整清单」「查看团队价格」。

### 分页型要点

- 首页服务多类读者而不泛泛，给不同意图清楚的路。
- 落地页一个信息一个动作，标题对上流量来源，在一页里把论证讲完。
- 定价页帮读者选档，化解「我该选哪个」的焦虑，让推荐档一眼可见。
- 功能页按功能、好处、结果推进，给场景和例子。
- 关于页讲为什么存在，把使命接回客户好处，仍放一个按钮。

### 交付

按区块给文案。关键处注明选择理由，标题和按钮给 2 到 3 个备选并附理由。需要时附页面标题和描述。写完过 check.md 的体检，营销腔按稿件语言查 patterns-zh.md 的宣传语或 patterns-en.md 的套话与堆砌词；其他语言按 check.md 文末通则处理。

## 二、工具站页型

一批工具站页面走 `cards/site-page.md`，那里管输入、必读和完成标志；这一节只管每种页怎么写。官方要求见 `official/google-content.md`，冲突时官方优先。

### 工具首页

- 首屏先让人用上：工具或上传入口就在首屏。标题直说这个工具做什么，副标题补读者最在意的条件（免费额度、文件大小、要不要注册），每条都能在产品里找到。
- 往下依次是：怎么用（3 到 4 步，每步写动作和结果）、能处理什么和不能处理什么（格式、上限、文件怎么处理）、和替代办法的具体差别、FAQ、到长尾内页的链接。
- 读者是来办事的，少讲品牌故事，多讲他要的结果。目标短语自然出现在标题、H1 和第一段，不为凑次数重复。

### 长尾内页

- 一页一个具体任务：某个平台上怎么做、某种文件怎么处理、某个限制下怎么办。动笔前写一句「搜这个词的人来这页要办成什么」。
- 主体是只属于这一页的东西：这个场景的步骤、这个场景特有的限制和坑、一个具体例子。通用介绍一两句就够，链回首页。
- 互换检验：两页的目标短语对调后仍读得通，就是模板换词。重写，或建议 rankup 合并成一页。
- 工具在这个场景做不到的，不写成能做到；做得到但有条件的，把条件写在第一次提到的地方。

### FAQ

- 只收真实问法：rankup 给的问法、客服记录、搜索建议、社区帖子。没人问的不自问自答凑数。
- 答案第一句直接回答（能或不能、一个数字、第一步做什么），再补条件和限制，两三句够了就停。
- 一页的 FAQ 只答和这页有关的。几页都会被问的同一个问题，只在一处完整回答，别处换成本页特有的问法。
- FAQ 要在页面上真的显示出来，不只写进结构化数据。

### title 与 description

- title 说清这页是什么、帮谁办成什么。品牌放最后，用 `|` 或 `-` 隔开，不用破折号（check.md 红线）。每页的 title 都不一样。
- description 用一两句写这页能让人办成什么，加一个具体差别（免费、不用注册、支持哪些格式）。只写正文里有的，它是摘要，不是关键词列表。
- 两者都是正文的承诺，正文兑现不了的不写。
- 长度：`check.py --meta` 报字符数和批内重复，只作提示。官方怎么生成和显示 title、摘要见官方层第四、五节，字符区间是经验口径，见经验层。
- 批量页：先写正文，再逐页写 title 与 description；`--meta` 报出重复的逐个改开。
