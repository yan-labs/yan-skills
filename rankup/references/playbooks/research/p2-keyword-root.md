## P2 · 词根调研：这个词能不能做、扩成树

### 触发

「这个词能不能做」「调研一下这个关键词」「这词难不难」「值不值得进」「KD 才 12，能做吗」
「我想做个 XX 的站，行吗」「围绕 XX 挖点词」「帮我扩词」「研究一下长尾词」「我只有一个词根」
「这批词还能再扩吗」「我这站还能做什么词」

### 为什么社区验证必做：数据平台的 28 天盲区

旧标题保留作兼容入口；新词、面板滞后、短时窗口及失败口径只见 [trends.md](../../trends.md#短时窗口用-trends-的过去-1-小时--4-小时--1-天--7-天验证刚出现的新词)，社区原话按 [demand-sources.md](../../demand-sources.md) 选源，不再设社区必测裁决线。

### 否决前必须反查：只看种子词判「不做」是禁止的

裁决只见 [entry.md「判读」](../entry.md#4--判读)；这里写全反查操作，复用问法链路产出的竞对与词，不另设市场门槛。

| 动作 | 操作 | 留证 |
|---|---|---|
| 站找词 | 从 ChatGPT 竞对清单与逐问法 Google 结果定位同任务站点；用官方 `site_keywords <域名> --gl <国>`、Semrush organic positions 或 sitemap slug 补实际措辞与落地页；保留免费工具词、内容长尾词、本地语词 | 站点 / 发现问法或结果 / 词与目标 URL / 来源、国家、日期；域级流量与搜索占比只作背景 |
| 词找站 | 对汇出的长尾问法与新词逐条查 Google，按 [seo-serp.md](../../seo-serp.md#逐问法-google-读法)建卡；返回同类站补站找词 | 问法→Google 卡→竞对→词表的关系；已覆盖、未发现、不适用或采集失败分别记 |
| 补漏回流 | 与已有问法池做差集，记录新说法、新任务和新竞对；新意图回主流水线补 GT 与问法链路，同意图复用有效证据 | 增量清单与补测状态；未找到新词不冒称不存在 |

【实测】站找词/词找站对照实验：同一方向，种子词法与反查法估出的盘子可以相差一个数量级以上，差异全在具体平台 + 具体场景的长尾词；也有方向反查后仍然小，说明反查能同时防止误杀与误留。

【实测】单次案例：某新兴方向候选在选品阶段被否决时，全程未反查该赛道已存在的站点真实措辞，否决判断建立在调研者自己临时猜测的 1–2 个候选词之上——单案例级别的流程缺口验证，非大规模统计结论。

### 流水线

端到端顺序只见 [entry.md](../entry.md#3--流水线)；先读已有入口卡，只补缺项，不把探索与反查提前当成裁决。

#### 五个取数动作与编排（探索循环）

目标是找到同一用户任务的真实说法与页面切口。种子词只是入口；相邻任务只有属于用户授权范围时才纳入，不能为了扩大词池切换方向。

| 动作 | 输入与通道 | 产出与回流 |
|---|---|---|
| 词→问题 | 已有问法池为起点；按需补 Google PAA/related、`translate_demand` 或社区原话 | 新问法与来源；采样方法只见 [seo-geo.md](../../seo-geo.md#步骤-2探针采样) |
| 词→站 | 逐条长尾问法查 Google；官方 `serp` / `serp_review` 补结构化数据 | Google 卡与同任务竞对；读法只见 [seo-serp.md](../../seo-serp.md#逐问法-google-读法) |
| 站→词 | 对发现的竞对用 `site_keywords`、organic positions、本地页面或 sitemap 取词 | 真实措辞、目标页与非种子词根；按上文反查表留证 |
| 站→站 | `search_known_sites`、SERP 共现域名、竞品页面引用 | 新竞对回站→词；没有域名则记不适用 |
| 词→词 | `keyword_ideas` 的 ideas/suggestions/related、`search_known_keywords`、三引擎下拉、`word-roots.mjs` | 近义、上下位与变体候选；标模板假设或实际来源，回问法池做差集 |

| 起手信息 | 编排入口 |
|---|---|
| ① 有词根 | 主流水线 0–1 取证后，逐问法词→站，再站→词/站→站/词→词补漏；新意图回 0–1 |
| ② 只有问题 | 记录用户原话与任务，提候选词；没有主词先走阶段 0.5，出现主词回① |
| ③ 有域名 | P4 反查实际词与页面，主词出现后回①；收入核验不代替关键词裁决 |
| ④ 什么都没有 | P1 按 [demand-sources.md](../../demand-sources.md)收集候选，提词后回① |
| ⑤ 非英语市场 | 阶段 0.7 记录 locale，按本节小语种三关补本地词；主流程与①相同 |

**工作量边界**：沿用单词根最多两层（根→L1→L2）、站→站最多两跳、探索最多三轮（一轮覆盖适用的五个动作）。它们只限制工作量，不决定市场结论。第二层按尚未覆盖的问法、任务与授权范围安排，不按“存活叶子”或 KD 排序；达到上限就列待补项。

每轮在报告第 3 节写 `动作 | 输入 | 新增词根数 | 新增站数 | 触发器 | 备注`；触发器沿用 `未触发 / 已触发-已换动作 / 已触发-未换动作（原因）`。新增只剩种子前后缀时切换动作，不把“必须找到非种子词”当完成门槛。适用动作已覆盖且没有新任务/说法时可停止探索，未找到和采集失败分开记；结论仍回 [entry.md](../entry.md#4--判读)。

#### 阶段 0.5 · 词根从哪来（没给词根时必跑）

「研究下长尾词」「我这站还能做什么词」这类话里没有词根。**没给词根不是回退到 P1 的理由，也不是反问的理由**——
按下面的回退链把词根挖出来。**任何一档拿到 ≥3 个词根就停，进阶段 0。**前五档都不需要用户开口。

| 档 | 前提 | 跑什么 | 拿到什么 | 拿不到就下一档 |
|---|---|---|---|---|
| **a · 项目已有词表** | 在一个项目根里 | `test -f .rankup/keywords.md && head -80 .rankup/keywords.md` | 标「做」的那些词，直接就是词根；同时看到口径与日期 | 文件不存在 / 全是 ⬜ → b |
| **b · 项目定位** | `.rankup/` 存在 | `head -60 .rankup/PROJECT.md`；再 `head -40 .rankup/INDEX.md` | 定位与目标用户里的名词短语就是第一版词根 | `.rankup/` 不存在 → c |
| **c · 站点自己在打什么词**（**主力档**，和 [`site-review.md`](../site-review.md) D1 同一招） | 手上有站点地址；**没有就先去 [`site-review.md` 阶段 0.0](../site-review.md#阶段-00--站点地址从哪来先取址再体检)取址** | `node $RANKUP/scripts/seo-audit.mjs --sitemap <sitemap> --json > /tmp/k/audit.json`（**没有 `--out`**，用重定向）<br>`jq -r '.[].overview.title.text // empty' /tmp/k/audit.json \| sort \| uniq -c \| sort -rn \| head -30`<br>`jq -r '.[].headings[]? \| select(.level==1) \| .text' /tmp/k/audit.json \| sort \| uniq -c \| sort -rn \| head -30`<br>再 `node $RANKUP/scripts/seo-audit.mjs --sitemap <sitemap> --density-only`（全站聚合的 1/2/3-gram） | 全站 title/h1 里反复出现的名词短语 + 高频 2/3-gram = 站点**实际在打**的词 | 没有 sitemap 时改逐页：`node $RANKUP/scripts/seo-audit.mjs <url1> <url2> … --json`。全站抓不动 → d |
| **d · 从域名反查**（只有一个域名时） | 手上有域名 | `node $RANKUP/scripts/demand/sitemap-diff.mjs --domain <域名> --all --slug-words --top-words 40`（零配额）<br>官方 `gefei-competitor` Skill 的 `site_keywords` / `search_known_sites`<br>还不够再 `node $RANKUP/scripts/demand/domain-profile.mjs <域名>`（**官方 domain_overview 当前每域 2 积分，以目录为准**，出「核心搜索词」） | slug 词频里的词族 + 域名画像给的核心搜索词 | 全部空 → 先按 [铁律二](../research.md#四条贯穿全部流水线的铁律)开 manifest 分辨「采集失败」还是「站真的没内容」，再 e |
| **e · 转 P1 自造词根** | 什么都没有 | 直接跑 [P1 的第一小时子集](p1-discovery.md#第一小时最小可执行子集面对-24-个脚本不要发呆先跑这-6-个) 1a–1f，从榜单候选域名里挑 3–5 个同赛道站，再回本表 d 档对它们做 slug 词频 | 从真实需求信号里长出来的词根 | 这一档**不会失败**——1a/1e/1f 几乎不依赖任何前提 |
| **f · 只剩这一档才问** | 上面五档全落空 | 发一句话，**同一条消息里阶段 0 和 e 档已经在跑**，不等回答：「给我一个词根或者一个网址就行；没有的话我按 `<c/d/e 档里最像的那个方向>` 先跑一轮。」 | 一个词根，或者用户默认你的猜测 | 用户不回 → 按你自己反推出的方向跑下去，**不许停在这里等** |

反推出来的词根是「这个站现在在打的词」，不是「应该打的词」。写进 `.rankup/keywords.md` 时标来源 `阶段 0.5-<档>`，
本节的站找词差集用来检查这批词根漏了哪些真实说法。

**【经验】词根按四类来源列全，再进阶段 2 扩树。** 上面六档回答的是「词根从哪挖」，这一条回答
「挖到的这批词根齐不齐」——四类各列几个，一起进扩树：**产品词**（用户可能直接搜的工具/产品叫法）、
**动作词**（他要完成的那个动作：转换、去除、生成、翻译……）、**场景词**（在什么场合下会用到）、
**用户原话**（社区帖、差评区、问答站里出现过的自然表达，取法见
[`demand-sources/users-and-launches.md`](../../demand-sources/users-and-launches.md) 八）。两条纪律：第一版**不要追求「最准确的那个词」**，
四类各有几个就够开扩树，准不准交给主流水线的问法与 Google 证据核验；**场景词留到扩树时再组合**——
一上来就把场景堆进词根，第一版词池会散掉，后面每一层扩的都是噪声。
（独立开发者出海经验分享，外部经验帖，未经本库实测）

**候选来源是第三方词站的「找词还原现场」页时，来源证据补记下表**（选填，只记线索来源，不替代 GT 卡）。
【实测，2026-11-12，免费样例页 [示例](https://new.web.cafe/keywords/arctic-char-meaning)】该页含发现词根、当时榜单是否留有记录、热度对比的词与基准、测量日期与倍数、首次有量时间、新旧趋势、SERP 查询与查得日期；GT 链接取自页面实际 href。

| 记录项 | 写什么 | 不要这样读 |
|---|---|---|
| 词根 | 站方标注的发现词根 | 样例页明确「没有当时榜单记录」，只说明复核时挂在该词根下，不证明它就是发现来源 |
| 当时榜单 | 缺失 / 留有记录；站方首次出现日期 | 缺失不当作"未出现过"；首次出现日期是站方口径 |
| 复核日期 | 你打开页面核对的日期 | 页面是历史快照，排名与热度以当天重查为准 |
| GT 原链接 | 历史窗口链接与当前窗口链接各存原 URL，不改写 | 历史链接重建的是窗口，谷歌今天重算的结果不保证与当时一致 |
| 市场 | 链接带 `geo` 记该国；无 `geo` 记「未指定市场」 | 样例链接无 `geo`，不能冒充目标国家数据 |
| 站方倍数 | 原样记为"站方读数"，附基准词与测量日期 | 不当真实搜索量；在目标市场仍按 [trends.md](../../trends.md#gpts-基线判读到底怎么才算有搜索量唯一判据源) 独立复核 |

批量取页只在两个免费样例上通过（HTTP 200 且含模块标题与 GT 链接），解析全字段、大规模抓取和官方批次详情是否含完整模块均未验证。

#### 阶段 0.6 · 词根说法不确定时先站找词（新兴方向必跑）

候选是自己临时拼出的猜测词、尚无共识叫法时，用该词与资讯原话定位同任务站点；按上文[反查操作](#否决前必须反查只看种子词判不做是禁止的)取真实词与页面，和猜测词一起进入主流水线。这里只补齐输入，不在 GT 后、采样前插入另一套市场测试。

【实测】单次案例：某新兴方向候选调研中，全程只凭调研者临时拼的 1–2 个候选词直接扩树，未反查该赛道
已存在的站点真实措辞——单案例级别的流程缺口验证，非大规模统计结论，仅作为本阶段存在的依据。

#### 阶段 0.7 · 非英语市场开工卡（目标市场非英语时必填）

**触发**：阶段 0 判定某国的搜索用户以本地语言为主（`hl` 非英语）。**先把这五件事逐条写清楚，
再进主流水线**——顺序反了，扩出来的词和实际接的页面会对不上：

| # | 写什么 | 要点 |
|---|---|---|
| 1 | 核心词 | 产品帮用户完成的那个动作，不是产品名 |
| 2 | 目标语言 + 国家 | 精确到「语言-地区」（`es-MX`、`es-ES`、`pt-BR`、`pt-PT`、`de-DE`……）；**同语言不同地区的用户不是同一批人，不按语言合并**——延续阶段 0「逐国查，每国一组」的原则，只是把粒度说清楚：语言相同不等于可以共用同一组 `(gl,hl,db)` |
| 3 | 产品卖点 | 页面准备突出的一两个优势 |
| 4 | 目标用户与场景 | 谁在什么情况下用 |
| 5 | 预设页面类型 | 产品页 / 工具页 / 博客页 / 对比页——**阶段 2 拿到 Google 卡后必须回头核对这一栏**：首页页面类型和这里预设的不一样，就改页面类型或换词，不能揣着错的预设往下扩树 |

五件事写进调研报告第 1 节，不替代阶段 0 的 `gt.py` 取数命令，只是先把「查什么、给谁查、准备接成
什么页面」定下来——首页全是教程却拿功能介绍页去打，从一开始就没接住意图。
**【经验】（独立开发者出海经验分享，外部经验帖，未经本库实测）**

#### AI / App 组合扩词（阶段 2 默认分支）

每个词根在保留原词的同时，检查两组自然表达：**关键词 + AI** 与 **关键词 + App**。
英文同时试 `AI <关键词>` / `<关键词> AI`、`<关键词> app` / `<关键词> apps`；按实际语序取词，
不为凑数量强拼。例：`AI crochet pattern generator`、`crochet pattern app`、`conduit bending app`。
有原生使用场景时，再从真实联想、竞品词或用户原话补 `for Mac` / `iPhone` / `iPad`；
不是把所有平台后缀做笛卡尔积，也不把 Android 纳入产品交付。

- 组合词来源标实际发现或模板假设，合并去重后回问法池；新任务按主流水线补证据，原词的量不替代组合词读数，变体量不直接相加。
- AI 词可能找生成工具、教程或资讯；App 词可能找下载、商店推荐或品牌。意图与页面承接只按 [seo-serp.md](../../seo-serp.md#逐问法-google-读法)核验。
- 有原生场景的组合进入 [App 市场验证分支](../research.md#app-市场验证分支)，保留离线、设备能力与使用习惯观察；客户端形态交规划阶段，不增加关键词裁决票。
- 没有新增说法或任务就停止该分支，工作量沿用上文两层边界。

#### 关键词竞争与竞品页面证据（P2 / P4 共用）

页面盘面、上线时间、目标 URL 非品牌自然量与任务缺口的证据读法只见 [seo-serp.md](../../seo-serp.md#逐问法-google-读法)；KD 的处理只见 [entry.md](../entry.md#选词判据只看两个)。

竞品页面报告先离线分流：已有 AITDK 完整 JSON 时按 [seo-box.md「AITDK 研究报告离线分流」](../../seo-box.md#aitdk-研究报告离线分流)读摘要，按证据引用定点回读；复用有效采集，不重跑面板。

#### 小语种候选词三关与本地竞品取词

本地竞品页面取词：复用 Google 卡里的目标页；有 AITDK 报告就读已存 Density，没有则用 `node $RANKUP/scripts/seo-audit.mjs <url1> <url2> … --density-only`，再记 Title/H1/目录/FAQ 的实际措辞。关注产品叫法、共现词、本地场景与英文页少见表达，来源标 `本地竞品`；不是照抄密度。

翻译或 AI 造词先标 `翻译假设`，以下三关只核对表达与证据覆盖，未确认项保留候选状态，不据此判杀：

| 关 | 核对什么 | 方法指针 |
|---|---|---|
| ① 语义确认 | 目标地区下拉、相关搜索、本地 Title/H1 的实际说法；可用母语者意见补证，没找到不直接判翻译腔 | 本节本地页面取词；问法池与来源见 [seo-geo.md](../../seo-geo.md#步骤-2探针采样) |
| ② 搜索确认 | 记录本地搜索表达及 GT 卡，国家与语种分开保留 | [trends.md](../../trends.md#gpts-基线判读到底怎么才算有搜索量唯一判据源) |
| ③ SERP 确认 | 逐问法记录真实意图与页面承接；对标竞品、本土垂直站只作盘面观察 | [seo-serp.md](../../seo-serp.md#逐问法-google-读法) |

【经验】本土垂直站一次排过大站可作为补查线索，不能仅凭一次排名下结论（独立开发者出海经验分享，外部经验帖，未经本库实测）。
