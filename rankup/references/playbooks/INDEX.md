# 预制流水线（playbooks）

**一句话进来，下一秒该跑什么。**

任务入口只有一处：[`SKILL.md`「任务入口」表](../../SKILL.md#任务入口)，每类任务指向一个第一站，第一站就是本目录里的某张开工卡。
本文件不再放路由表，只定义开工卡怎么写，以及几条跨卡的分流规矩。
[`capability-map.md`](../capability-map.md) 回答「有哪些能力」，各 `references/*.md` 回答「怎么判断」，
本目录回答**「先跑哪个、再跑哪个、谁能并行、产出喂给谁」**。

真实用户不会说「跑一下 seo-audit.mjs」。他会说「做个研究」「review 一下我的站」，然后期待立刻有事情发生。
**读完对应那张卡就能开跑**；只有到了判读环节才去翻卡里指的判据。

## 跨卡的分流规矩

- **看用户交给你的是什么输入，不看他说出口的名词。** 调研只有三种输入：一个词（一律当词根）/ 别人的域名 / 什么都没有；
  细分表只在 [`research.md` P0](research.md#分流规则只看输入三种形态)。
- **「他没给我 X」不是反问的理由，是去挖 X 的信号。** 没给词根 → `research.md` P2 阶段 0.5；没给域名 → `site-review.md` 阶段 0.0。
  两处都给了完整回退链，走到最后一档才允许问一个问题。
- **同时命中两张卡**（「帮我看看这站还能挖什么词」= 体检 D 组 + P2）：先跑体检拿到现状，再拿现状喂调研；
  反过来会用一批没有落点的词去查配额。
- **方向在前，主词在后。** 用户给的是方向、想法或「选品」时先进 [`selection.md`](selection.md)（零配额判据在前）；
  主词出现后先过 [`entry.md`](entry.md)，再进 [`research/p2-keyword-root.md`](research/p2-keyword-root.md)。
  不要先花配额把词表拉全再回头筛硬约束：绝大多数配额会烧在免费判据就能秒杀的候选上。

**旧编号**：3.0 之前的「P2 这个词能不能做」与「P3 扩词」已合并为 P2 词根调研。

## 贯穿所有 playbook 的铁律

唯一源在 [`research.md`「四条贯穿全部流水线的铁律」](research.md#四条贯穿全部流水线的铁律)：脚本只采集、判决你下；
0 条先开 manifest 再说「没有」；一个配额工具同一时刻只许一个采集器；哥飞开放 API 直接取数、Rankup 自己判读。
其他 playbook 同样适用，本文件不复述。

## 开工卡的格式（每张卡都这样写，不要自创）

每个 playbook 文件开头是一张 `## 开工卡`，≤80 行（`doc-lint.mjs` 检查），其后可以有正文。卡的第一行固定是
「被派单的执行者先读 [`../executor.md`](../executor.md)。」（子目录里按相对路径写），然后依次是：

1. **触发**：用户会说的原话，收几种不同的模糊说法。
2. **输入**：开工前要有的东西，缺了去哪取。
3. **步骤**：按顺序的命令或动作，可直接复制；能并行的写明。
4. **读哪里**：要读的 reference 小节，带锚点。
5. **完成标志**：怎样算做完，证据落在哪。
6. **收尾**：结论写回 `.rankup/` 的哪个文件。

**判据和阈值不进卡。** 它们只在 [`checklists.md`](../checklists.md) 与 [`entry.md`](entry.md)，卡里只给锚点；
抄一份进卡就成了第三份副本，下次改阈值必然漏一处。

长流水线（`research.md`、`site-review.md`）的正文仍用五列表：`阶段 | 并行/串行 | 跑什么 | 拿到什么 | 卡住了怎么办`，
并写清各步的配额档位。

**禁止出现「按需选择」「参考相关文档」这类表述**：那等于把猜测又推回给下一个读者，
而这一层的全部价值就是消灭那次猜测。
