# 设计组件库参考站：搭架子之外的视觉层

**这份文件的用途只有一个**：脚手架（`shadcn init --preset …`）解决项目结构，
`components/ui/` 解决基础控件，但**页面级的视觉设计——Hero 怎么排、动画怎么做、
landing page 用什么布局——脚手架不管，组件库也不管**。
下面这批外部站是真人设计工程师做的现成案例，AI 在做页面设计时**必须先去翻一遍**，
找到合适的再适配进项目，而不是凭空画。

三条阅读约定：

1. **这些是参考，不是依赖。** 不要 `npm install` 它们的包或把源码整段复制；
   看到合适的组件，理解它的设计思路和实现方式，然后用项目自己的 shadcn 组件库
   和技术栈**重新实现**或**适配**。部分站（如 21st.dev）提供可直接粘贴的 prompt，
   这种可以直接用，但产出的代码仍须符合项目的组件规范。
2. **浏览有目的。** 不是打开首页随便逛——带着具体的页面需求去搜分类
   （Hero / Footer / Background / Card / Navigation / Pricing），
   看 3–5 个案例就够做决策，不要把整个库扫一遍。
3. **这份表会持续扩充。** 每收录一个新站，写清楚它和已有站的差异覆盖，
   不要堆一列功能相同的站。

## 收录站

### 21st.dev

| | |
|---|---|
| **地址** | https://21st.dev |
| **定位** | React + shadcn 生态的社区组件库，12000+ 组件、模板和主题 |
| **与项目技术栈的关系** | **直接兼容**——基于 shadcn，和我们的脚手架同一套生态 |
| **核心分类** | **Marketing blocks**（animated heroes、hero sections、shaders、liquid & metal effects、backgrounds、gradients、footers）<br>**UI components**（buttons、AI chats、cards & grids、galleries & 3D、navigation、sign-ins & widgets）<br>**Templates**（完整页面模板）<br>**Themes**（shadcn 主题变体） |
| **使用方式** | 组件以 prompt 形式分发——复制 prompt 粘贴到 Claude Code 即可生成适配当前项目主题的组件代码 |
| **什么时候去看** | 做 landing page、Hero 区、定价页、页脚、404 页、登录页等**页面级设计**时；需要动画、动效、渐变背景等视觉效果时；找不到设计灵感时 |
| **什么时候不要去** | 只需要基础 UI 控件（button、input、dialog）时——那些直接 `shadcn add` |
| **入口 URL** | 组件：`/community/components`；模板：`/community/templates`；主题：`/community/themes`；按分类：`/community/components/s/<分类>` |

### Libraries.dev

| | |
|---|---|
| **地址** | https://libraries.dev |
| **定位** | React 视觉特效库集合——5 个独立 npm 包（border-beam、thinking-orbs、liquid-gooey、metal-fx、img-fx），专注动效和着色器效果 |
| **与项目技术栈的关系** | **直接兼容**——React 18+，零运行时依赖（img-fx 除外需 three），MIT 开源；和 shadcn 组件库互不冲突，特效叠在组件上 |
| **核心分类** | **Border beam**（彩虹光圈沿边框跑动）<br>**Thinking orbs**（AI 接口的思考态加载球）<br>**Gooey**（液态融合变形效果）<br>**Liquid Metal**（实时铬金属环，按钮和图标用）<br>**Image generation**（WebGL 图片生成加载器） |
| **使用方式** | 每个库以 prompt 形式分发——复制 prompt 粘贴到 Claude Code / Cursor，agent 自动 `npm install` 并接入项目；Pro 版解锁 Studio 深度定制 |
| **什么时候去看** | 需要**动画特效、加载态、边框光效、液态/金属质感**等视觉点缀时；给 AI 功能做 thinking 状态指示时；想给按钮、卡片、图标加微交互时 |
| **什么时候不要去** | 需要页面级布局（Hero、定价页、页脚）时——那是 21st.dev 的覆盖范围；需要基础控件时——直接 `shadcn add` |
| **与 21st.dev 的差异** | 21st.dev = 组件和页面模板（广度），Libraries.dev = 动效和着色器特效（深度）；两者互补，不重叠 |
| **入口 URL** | 各库 playground：`/beam.html`、`/orbs.html`、`/gooey.html`、`/metal.html`、`/image.html`；使用说明：`/how-to-use.html` |

## 页面模式案例：多功能站信息架构

**这类条目和上面「收录站」的区别**：收录站（21st.dev、Libraries.dev）是可以持续浏览、按分类挑组件的库，冲着"找灵感"去逛；这里收录的是从某个真实产品站观察到的、单一但完整的信息架构/交互模式，一次只收一个模式，不追求站点覆盖度，用来解决"遇到这种具体场景该怎么设计"的问题。

### 侧边栏做全站功能导航 + 首屏做成"工作台"

| | |
|---|---|
| **案例站** | https://videocompress.ai（站点会按浏览器语言自动重定向到本地化版本，实测触发过日语版；本次验证主要看的是英文路径如 `/video-cutter` 与显式中文路径 `/zh-CN/video-cutter`，两者信息架构和交互完全一致） |
| **模式** | 左侧是常驻的可折叠目录树侧边栏，把站内每个功能分组列出——"压缩"（视频压缩、图片压缩、PDF 压缩）、"编辑"（视频剪切、裁剪视频、音频裁剪）、"转换"（转 MP3）、"AI 工具"（视频转文字、视频翻译、PDF 翻译、图片翻译）——点击侧边栏项直接跳转到对应功能页，当前页在侧边栏里高亮；用侧边栏取代了常见站点"其他功能塞进顶部 header 下拉菜单"的做法（本站顶部 header 同时也有一个「製品/Products」下拉菜单，但内容和侧边栏重复，侧边栏是主入口）。右侧首屏直接是功能工作区（拖拽上传框 + Choose File 按钮），不是营销文案 |
| **解决的问题** | 多功能站常见做法是把其他功能塞进 header 下拉菜单，用户要点开才知道还有别的功能，发现成本高；侧边栏常驻展示，一进站就能看到"这个站还能做什么"，发现成本更低——尤其适合"一个域名下挂多个相关小工具"的站，这是把流量导到站内其他功能页、降低跳出率的低成本手段 |
| **首屏"工作台"而非"营销页"的心理效应** | 首屏直接是可以拖文件上传的工作区，让用户第一眼感觉"这是个可以立刻用的工具"，而不是"要先看介绍的产品页"，转化路径更短、跳出更少 |
| **没有牺牲 SEO 内容** | 首屏工作台之下依然是完整传统 landing page 内容——实测 `/video-cutter` 页面往下依次是「How to Use」三步说明、6 张功能卖点卡片、使用场景说明（社媒剪辑/清理录屏/职业用途）、用户评价（"Listen to these real voices"）；没有滚动到页面最底部逐一确认是否还有独立 FAQ 板块，但正文密度已明显达标。这跟 rankup「每页正文内容要有密度」的硬规则不冲突，工作台首屏和 SEO 正文可以两全 |
| **移动端处理** | 已用 `resize_window` 实测 375×812：侧边栏默认完全隐藏，header 只留一个汉堡按钮；点击后侧边栏以全高左侧抽屉（overlay）形式滑入，带暗色遮罩盖住主内容，抽屉内容和桌面端一致（分组、当前项高亮、登录卡片、Pricing/Download/Language）。桌面宽屏（实测 1600×900）侧边栏常驻展开，另有一个「Collapse sidebar」按钮可把它收起为仅图标的窄 rail（无文字标签）；中等桌面宽度（未显式设置、浏览器面板默认渲染约 1024×768 时）已经和移动端一样退化成汉堡抽屉模式，说明"常驻展开"只在较宽的桌面视口下出现，具体切换断点的像素值没有精确测出，只确认了区间在 1024～1600px 之间 |
| **适用边界** | 只适合**一个域名下挂多个相关工具/功能**的站（本例：视频/图片/PDF 处理工具集合）。单一功能工具站（整站只做一件事）或纯内容站没有"侧边栏导航一堆功能"的需求，硬套这个模式反而会画蛇添足、挤占首屏空间 |
| **技术实现** | 已查 shadcn/ui 官方文档（`ui.shadcn.com/docs/components/sidebar`）确认现成有 **Sidebar** 组件，官方原话就是"A sidebar that collapses to icons"，`pnpm dlx shadcn@latest add sidebar` 一键装；组合方式是 `SidebarProvider > Sidebar(SidebarHeader/SidebarContent[SidebarGroup > SidebarMenu > SidebarMenuItem > SidebarMenuButton]/SidebarFooter)`，移动端内置切到 Sheet 做抽屉 overlay——和本站实测的折叠、图标 rail、移动端抽屉行为高度吻合，可以直接拿它实现这类应用外壳，符合我们的组件库红线，不用手搓 |
| **验证方式** | 2026-09-15 用浏览器工具实际打开站点截图 + 读 DOM 验证，覆盖首页、`/video-cutter` 子页、`/zh-CN/video-cutter` 本地化版，以及 1600×900（桌面宽屏）、约 1024×768（中等宽度）、375×812（移动端）三档视口 |

### 多功能工具站侧栏统一规范

以下是我们在多功能工具站实施并经用户确认的统一规范（2026-09-15），**不是上方案例站的观察结论**。适用于一个域名承载多个相关工具、采用 shadcn Sidebar 工作台布局的站；具体实施和回归证据留在各项目 `.rankup/`。

| 项目 | 实施与验收要求 |
|---|---|
| 品牌与主页入口 | Logo + 站名放在侧栏顶部，复用网站原有品牌色，不统一强制蓝色；Logo 链接主页，不再增加重复的全局 Home / All tools 菜单。分类内的 All Image tools 等聚合入口可保留。 |
| 桌面与手机布局 | PC 隐藏独立顶部 header，移除其占位；手机保留 header，用它打开 Sheet。CSS 与 Sidebar 的 `use-mobile` 使用同一断点，默认 1024px，可按内容校准并共同修改；这是实施默认值，不是案例站的精确观测值。 |
| 展开与收起 | PC 展开态的收起控件在侧栏顶部、Logo 右侧同一行；收起为窄 rail 后，顶部保留展开图标，不要求同时显示完整 Logo + 站名。默认使用纯 PanelLeftClose / PanelLeftOpen 图标，不另起整行，也不依赖底部或悬浮入口。提供准确的 `aria-label` / `title`、键盘操作和足够的点击区域。 |
| 固定区与滚动区 | SidebarHeader / SidebarFooter 常驻，仅 SidebarContent 滚动；语言、主题等控件固定在底部。菜单弹层朝可见方向展开，不被容器裁剪；手机抽屉保持同样的分区与可达性。 |
| 目录与当前状态 | 当前页所属分组自动展开，叶子按实际路由精确高亮；手机点击链接后关闭抽屉。保留所有现有工具的真实链接，用工具清单与导航对账，不能只覆盖首页卡片或热门工具。 |
| 图标与样式稳定 | 首页、内页、硬刷新和 SPA 跳转的图标外盒与内部 SVG 尺度一致。通用 SVG 尺寸选择器不得递归覆盖嵌套品牌标记；图标自身显式指定尺寸类，避免 Button 默认样式缩放。关键 CSS 与完整 CSS 加载后的行为一致。 |
| 必做回归 | 覆盖 PC 展开、图标 rail、H5 抽屉及断点两侧；核对 Logo 回主页和无重复主页菜单；滚动目录时底部位置恒定；菜单可见、ESC 关闭与焦点返回正常。实走首页 → 工具页 → 首页，再直接打开工具页硬刷新，比较品牌和控件的外盒、内部 SVG 尺寸。 |

## 使用时机：什么场景触发浏览

| 场景 | 动作 |
|---|---|
| 用户要求做一个「好看的」「有设计感的」「精美的」页面 | **必须先浏览**至少一个收录站的相关分类，找 2–3 个参考案例再动手 |
| 做 landing page / Hero / 定价页 / 关于页 | **建议浏览**——这些页面的视觉质量直接影响转化 |
| 需要动画、动效、过渡效果、背景特效 | **建议浏览**——特效类先看 Libraries.dev（border beam / orbs / gooey / metal），页面级动效看 21st.dev 的 animated heroes 和 shaders 分类 |
| 做内页、工具页、表单页等功能导向页面 | **不必浏览**——用 shadcn 组件库即可 |
| 一个域名下有多个相关工具/功能，要设计导航结构 | 参考上方案例评估适用性；采用侧栏工作台时执行[侧栏统一规范](#多功能工具站侧栏统一规范)。单一功能站/内容站不适用 |

## 浏览流程

1. **明确需求**：要做什么页面、什么区块（Hero / Footer / Background / …）。
2. **按分类搜索**：去收录站的对应分类页浏览，按热度排序看前几个。
3. **选 2–3 个候选**：截图或记录组件名，带回给用户确认方向。
4. **适配实现**：理解设计思路，用项目自己的技术栈实现。如果收录站提供
   可直接粘贴的 prompt（如 21st.dev），可以直接使用，但产出代码须检查：
   - 是否符合项目的组件目录结构（`components/ui/`）
   - 是否正确使用了项目的设计令牌（颜色、字体、间距）
   - 是否有占位内容（红线）
   - 响应式是否达标

## 与现有规则的关系

- **不替代 shadcn 组件库红线**：基础控件（下拉框、弹窗、日期选择、表格分页、Toast）
  仍然只准来自 `components/ui/` 或 `shadcn add`，这条不变。
- **不替代 `/imagegen`**：页面里的图片素材（logo、og:image、配图）仍然用 imagegen 生成，
  组件库参考站解决的是**布局和交互设计**，不是图片素材。
- **不替代段 4 体检**：参考外部组件做出来的页面，段 4 全套检测照跑。
