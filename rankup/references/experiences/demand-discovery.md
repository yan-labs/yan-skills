## 〇、贯穿全流程的一条元规则：**取数失败会伪装成一个否定答案**

【实测】2026-08-24 一夜之内在四个不同工具上撞到同一个失败形态，因此单列成规则。

工具拿不到数据时，**很少报错**。它更常见的做法是返回一个看起来有意义的否定值——
而那个否定值和「真的没有」长得一模一样：

| 工具 | 失败时返回 | 看起来像 | 真值 |
|---|---|---|---|
| 关键词难度工具 | 摘要行月搜量印 `—` | 「这个词量很小」 | 它根本没返回量 |
| 关键词量能面板 | `volume: 0, noData: true` | 「确认无搜索量」 | 复查三次都是 320 |
| 注册商查价页 | 空白卡片 | 「没有溢价标记 = 标准价」 | 重抓后是溢价档 |
| 流量面板批量模式 | `below-floor, totalVisits: null` | 「这站没流量」 | 单查是 351,111/月 |
| 域名前世工具 | 「无任何历史快照记录」 | 「域名干净」 | CDX 直查有 41 条快照 |
| 诊断命令的退出码 | 退出码 0 | 「桥是通的」 | 扩展早已断连，状态只写在 stdout 里 |
| 页面上的「实时」计数器 | 三次采样数字不变 | 「这个方向没流量」 | 整页被 CDN 缓存了 6 天（`age: 521292`） |
| 付费接口的 `refunded: true` | 调用失败但声明已退配额 | 「额度已经补回来了」 | 紧接着查配额仍是 0，退款声明与实际到账不同步 |

**共同点：否定答案比缺失更有说服力，所以更不会被质疑。**
一个破折号还会让人犹豫，`noData: true` 和 `below-floor` 则像是工具在明确告诉你结论。

同一形状还有一个已经在别处记录过的实例，这里只交叉引用不重复收录：Google Trends 的
`compare` 只要组内有一个词低于阈值，**整组**都会返回「没有数据」，报错读起来像
「这几个词都没有搜索量」，实际只是其中一个词拖累了全组——见
[`trends.md`](../trends.md) 的「〇·五、对比是全组连坐」一节。

**第六个实例，也是代价最大的一个：把「还没发生」读成了「不会发生」。**

一个盘面里排第 6 的低 DR 站流量只有 9 访问/月，据此判定整条赛道进不去。
实际那个域名注册才 3.2 个月，首页 `<title>` 还是 WordPress 默认值——
它不是「做了但没成」，是**还没开始做**。而同一个盘面里另一个 9.8 个月的站，
自然搜索 9 万/月。缺的不是数据，是**给数据定位的那个变量（年龄）**，
而且它就写在同一份原始文件里，被跳过了。

推广开来：**一个否定观测在被解读之前，必须先确认它是不是「尚未发生」而非「不成立」。**
时间维度是这类误读的头号缺失变量。

**第七类，也是最常踩的一类：工具的默认参数自己制造假阴性。**

同一批探针，同一天，四个空结果全部来自没改的默认值：

| 探针 | 默认值 | 默认下的结果 | 放宽后的真相 |
|---|---|---|---|
| 扩展商店搜索 | `--min-users 100000` | 空 | 一堆 121–1000 用户的扩展 |
| 社区热度 | `--days 7` | 空 | 放到 3650 天有真实命中 |
| 论坛 RSS | `--delay 6000` | 空 | 被限流；`--delay 8000` 正常 |
| 通用网页搜索 | — | 普通结果 | **静默忽略了 `allintitle:` 操作符** |

这些默认值本身都合理——它们是为「已经知道自己在找什么」的场景调的。
但**探索阶段的第一次调用必须反过来：先把过滤器关掉、窗口开到最大，看清真实分布，再收窄。**
否则你测的是自己的默认值，不是这个世界。

操作规则：

1. **每个探针的第一次调用用最宽参数**（`--no-filter` / 最大时间窗 / 最慢速率），
   确认管道通了、数据长什么样，然后才谈筛选。
2. **拿一个已知有数据的目标做对照组**，再去跑真正关心的目标。
   实测有效：先用一个必然在榜的域名验证引荐榜脚本能返回真实行，
   之后 8 个竞品全空才可信为「确认为空」而不是「脚本坏了」。
3. **空结果的报告必须写明是哪一种**：「确认为空」还是「这次调用失败了」。
   两者对下一步的指示完全相反。

硬规则：

1. **只有零需要被证明是零。** 拿到零值 / 空值 / 「无数据」时，**换一种调用方式复查一次**
   （批量改单查、脚本改页面、换一个面板），两次一致才采信。
2. **非零值不必这样防。** 渲染失败会产出空值，不会凭空产出一个带 KD、CPC、
   地区分布、渠道构成的完整结构。反方向的风险不对称。
3. **决定「做不做」的那个零，必须复查到两次一致为止。** 一次读数不许定生死。

代价参考：本条规则没到位之前，同一晚上产生了一条写错的关键词结论、一条写错的域名定价、
一次差点把头部竞品判成「无流量」。

## 一、反推「谁已经在赚钱」的七条通道

这七条互不重叠，可以并行跑。共同点是：**不问用户想要什么，看钱已经流向了哪里。**

### 1. 支付网关引荐流量：把「到达付费页比例」当需求强度的代理指标

【实测】—— `我话事`，`bounty/fd0wrgx7fh`

`seo.web.cafe/referring/` 有 Stripe 引荐流量榜，但**光看榜只知道谁在赚钱，不知道谁赚得狠**。
多算一步：

```
到达付费页比例 = Stripe 页面引荐流量 ÷ 网站总访问量
```

原帖给的算例：某站 269.26 万 ÷ 3131.87 万 ≈ **8.60%**，即每 100 次访问产生约 8.6 次
进入收银台。再往下折算营收：

```
月营收 ≈ 月访问量 × 到达付费页比例 × 支付成功率 × 客单价
```

**两条必须一起记的边界**（原作者自己给的）：

- 能进 Stripe 引荐榜的站本身就是优等生，8.6% **不是行业平均值**，不能拿来当基线。
- 估算时用保守值（原帖建议按 1% 折算），别只算好的那一面。

### 2. 不要只盯 Stripe：长尾支付网关藏着可复刻的利基产品

【经验】—— `NightWatch` / `loading...`，`bounty/fd0wrgx7fh`

专精小微商户的支付网关（Creem、Lemon Squeezy、Paddle、FastSpring、Dodo Payments、
Waffo 等）的入站流量里，用户多是个人开发者或极小团队——**规模小意味着可复刻**。
方法同上：找到目标产品走的是哪个支付渠道，再分析这个渠道的支付子域名或路径，
反查还有谁在用。国内无执照场景对应虎皮椒、PayJS 一类。

> 这条与上一条是同一个动作的两个采样面：巨头渠道给你「天花板长什么样」，
> 长尾渠道给你「我明天能不能做一个」。

### 3. 广告投放数据：一直在投 = ROI > 1

【经验】—— `我话事`，`bounty/fd0wrgx7fh`

产品赚钱就会放量。所以**持续投放、或突然加大投放的产品，ROI 一定大于 1**，可以抄作业。
可用面板：小红书聚光、巨量（筛热门素材，打破信息差）；应用侧用 SensorTower、
七麦数据、点点数据看下载量与收入。

**【实测】的口径警告**：原作者对照过内部数据——**具体数值不准，趋势与量级对**。
面板写月收入 50K，真实值大致落在 40K–60K，但不会出现 50K 与 5K 这种量级差。
所以这类数字**只能用于排序和量级判断，不能进任何财务测算**。

### 4. 应用商店付费榜 + 差评区

【经验】—— `NightWatch`，`bounty/fd0wrgx7fh`

能长期挂在**付费榜**上的应用，说明核心诉求已被市场验证且用户有强付费意愿。
真正的机会在**差评区**：用户反复吐槽的同一个痛点，就是新产品的切入口。

### 5. 淘宝 / 闲鱼销量：搜索引擎看不见的需求

【实测】—— `我话事`，`bounty/fd0wrgx7fh`

竞品的安装包、使用教程在淘宝闲鱼月销几千份，本身就是需求证据；**更值钱的是去和店主聊**。
原帖的例子：面向研究生的工具，店主指出真实痛点是**专业论文翻译**——团队原本觉得
「研究生六级翻译都会，谁要这个」，上线后成为核心功能。

推论：一个 GitHub 上完全免费开源的东西，在淘宝上光卖安装包和教程就能卖几万份，
说明**「获取门槛」本身就是可收费的需求**，与功能是否免费无关。

### 6. 大厂会员功能表：优先抄「高级会员才能用 + 限次限量」的那些

【经验】—— `我话事`，`bounty/fd0wrgx7fh`

PDF 转 Word、图片 OCR、录音转文字，每一个都能找到免费开源方案或极简 API 实现，
但这些正是 WPS 一类产品会员收入的来源。**判据不是「技术难不难」，是「用户会不会做」。**

筛选优先级：**高级会员专属 + 限制次数/用量**的功能 > 免费会员就有的功能。
被厂商用配额卡住的，通常就是成本高、需求也硬的那些。

### 7. 站点自有计数器：第一方信号，但要先验活

【实测】

竞品页面上如果自己挂了一个计数器（今日已检测 XX 次、累计服务 XX 用户、已处理 XX 张图），
这是**第一方数据，比任何第三方流量面板估算都权威**——前提是你能证明它是活的。

反例：某站首页「Live Stats·Checked Today 847」在 3 分钟内采样三次，数字纹丝不动，
第一反应是「这个方向流量很低」。实际原因是页面被 CDN 整页缓存了——`curl -sI` 出来
`age: 521292`（折合 6.03 天）、`x-vercel-cache: HIT`，加查询串刷新也没用（CDN 会
把参数归一化掉，缓存键照样命中）。这个数字根本没在变，**不是低，是死的**。

操作规则：

1. **引用任何页面上的「实时」数字之前，先 `curl -sI` 那个页面**，看 `age` /
   `x-*-cache` / `cache-control` 三个头——陈旧值和真实静态值长得一模一样，只有
   响应头能分辨。
2. 验活后再采样：时间窗要长到「按它自称的速率，这段时间内应该能看出变化」，
   一次性抓取只能算一个不知道处于当天哪个时段的样本点，不能当作速率使用。
3. 验活失败也不必弃用——把它降级成「单一样本、时间点未知」，而不是直接
   当结论使用。

## 二、把筛选做成流水线（可全自动）

【实测】—— `秋北`，`bounty/fd0wrgx7fh`（该帖当轮最高分回答）

一条端到端的自动找词流水线，逻辑是：**如果一个新站能拿到非品牌词流量，
说明这个赛道不被老站霸占，对新站友好，窗口还开着。**

```
Product Hunt API（每天拉前一天发布的产品）
  → 解析产品真实网站
  → 查 AITDK：域名注册日期 / 月访问量 / 流量结构 / 核心搜索关键词
  → 按阈值筛选
  → 排除品牌词，只留需求词
  → 人工判断：方向是否感兴趣 + SERP 里的站我们能不能做得更好
```

原帖给的阈值（可按自己标准调整）：

| 条件 | 阈值 | 想筛掉什么 |
|---|---|---|
| 域名注册时间 | 1 年以内 | 只留新站，老站拿到流量说明不了赛道友好 |
| 月访问量 | > 3,000 | 确认真的拿到了流量 |
| 搜索流量占比 | > 20% | 确认流量来自搜索而不是发布日的一波曝光 |
| 直接访问占比 | > 20% | 有二次访问，说明确实解决了问题 |

**命中率【实测】：约每 300 个 Product Hunt 产品筛出 1 个符合条件的站。**
这个数字很重要——它说明这条流水线必须自动化跑，手工筛不划算。
原作者的部署方式是 Cloudflare Worker + cron，每天早上出结果。

**扩展方向**（原帖明说只做了 PH 一个源）：接更多导航站与榜单，同一套阈值直接复用。

> 对我们的意义：这正是本 Skill「可复用操作必须落成脚本」那条规则的典型对象。
> 若要落地，脚本进 `<project>/.rankup/scripts/`，阈值参数化，不写死。

### 漫游找词 SOP：广撒网找词的九步（可执行浓缩）

【实测】—— `程序员卡诺`，`new.web.cafe/tutorial/detail/fjdhxvvcsq`。
原文定位是「无特别领域的广撒网找词 SOP」，这里只留可执行部分。

**第 0 步是最容易被跳过、也最重要的一步：先合理化时间预期。**
时间分配是 **挖需求 40% / 开发 20% / 推广外链 40%**。
「2 小时找词」对应的前提是「半小时能上好一个站」；如果上一个站要两三天，
那花一周找词都不为过。**卡在「找了 2 小时还没找到」的自我怀疑里，是预期错了，不是能力不够。**

1. 打开任一关键词数据平台的关键词页。
2. **搜任意一个词根**，从自己有所了解的领域出发：具体对象、具体产品或品牌、分类，
   或直接用工具类词根库（见 [`../demand-sources.md`](../demand-sources.md) 第九·五节）。
3. **设筛选条件**：排除 NSFW；KD < 30（40 也可以看看）；按搜索量降序；
   结果太多再加 CPC 门槛；**有「搜索意图」字段的话把「导航」类去掉**——导航词抢不走。
4. （可选）换趋势工具路线：同样输入词根，**重点看底部的相关查询**。
5. **词海漫游**：逐词理解「用户在什么情况下会搜它」「搜它是为了拿到什么」。
6. **避开四类陷阱**：

   | 陷阱 | 例子形状 | 为什么不能做 |
   |---|---|---|
   | 搜索目标不可替代 | 某个专有系统的登录词 | 没有任何操作空间 |
   | 搜索引擎自己就解决了 | 一查就直接出图/出答案的词 | 没人往下点，排第一也没流量 |
   | 季节词 | 拉到一年看曲线是尖峰不是平台 | 一年只有几周有量 |
   | 对抗性工具 | 与平台规则正面冲突的转换类工具 | 流量强但新站不断被封杀 |

7. **进一步确定搜索量**：用趋势工具对标一个自己熟悉的参照词换算绝对量。
   （原文提的关键词规划师路线，评论区 2025-12 反馈**测试权限已经查不了流量**，别绕这条。）
8. **观察对手判断难度**：看首页是内页多还是主词首页多；用 `allintitle:` 数专门优化这个词的页面，
   算 **KGR = allintitle 页面数 ÷ 月搜索量**；再看已被注册的精确匹配域名现在什么状态。
9. **上站。**

**一条关于「工具能替到哪一步」的判断**：这套 SOP 的成本几乎全在**第 5 步的人肉理解**上，
评论区反复出现「一次得 2、3 小时」。脚本能替掉的是 1 / 2 / 3 / 6 / 8，**第 5 步替不掉**——
所以工具的价值是**把候选池筛干净，而不是替人做判断**。这条同时解释了
上面「规模化版本」为什么必须配一个人可调的筛选看板。

### 规模化版本：卡点不是缺方法，是执行不动量

【实测】—— `程序员卡诺`，`bounty/fd0wrgx7fh`

**这条是本章最重要的元认知，值得单独立一节。**

作者的判断是：社群里找需求的方法从来不缺——看榜单复刻、挖搜索词、去交易平台看什么卖得好，
都写得明明白白。真正的卡点是**没有人能长时间执行枯燥的挖掘动作**：

> 看榜单，很少有人做到只看第一名就立刻去复刻；一般看到第三第四个就已经不知道要做什么了。
> 从数据网站挖词，每次搜出来一屏词，每个词再去研究一遍搜索结果，研究几十个就受不了了。

**而不起量就得不到结果。** 所以这条方法论的结论不是「换个更好的方法」，
而是**把已知方法交给 agent 去跑量**。作者跑通的实际规模：

| 环节 | 量级 |
|---|---|
| 社群拿到的初始词根 | 119 个 |
| 扩展后词根 | 1,309 个 |
| Similarweb 扩出的关键词（broad + suggest） | 97,681 个 |
| 按 KD / 搜索量初筛 + AI 二筛（按「精品工具页」的形状筛） | 剩 800 多个 |

流水线用到的四个数据面：**Similarweb、SEMrush、Google SERP（serper.dev 一类）、
关键词难度估算（哥飞版）**。最后一步很关键：**用 SERP API 去看这个词的实际搜索结果**——
比如「拿这个关键词做域名的站多不多」，直接判断赛道有没有被占。

三条作者自己总结的心得，每一条都可以直接当规则用：

1. **不要追求全用代码解决所有链路。** 中间需要「人肉」调度的交给 agent；
   agent 都搞不定的，把自己填进去也没问题。
2. **合理设定筛选目标，不要怕浪费。** 目标是「精品工具页 + 关键词域名」时，
   初筛条件就该是 **KD 很低、搜索量不用高、有点 CPC 就行**——
   一个下午能做完一个工具页，几千到一万出头的月搜索量就值得上。
   换个目标（比如做大站）就换一套阈值，**不同目标不同策略**。
3. **多语言词根是被整个社群漏掉的一片矿。** 社群流传的词根全是英文，
   但中国人搜的是「JSON 编辑器」不是「JSON editor」。词根 × 语言的乘法会让量倍增——
   这正是只有 agent 跑得动的部分。

> 作者还专门给这堆数据做了一个看板来排序分类，理由是「方便人也参与进来，
> 快速调节筛选规则并看到反馈」。**全自动流水线 + 人工可调的筛选面板**，
> 是这条路线的完整形态，缺了看板那一半就会淹死在数据里。

### 闭环版本：词根 ←→ 榜单，两条路互相喂

【经验】—— `GONG`，`bounty/fd0wrgx7fh`

一句话：**构建以【词根】和【榜单】为核心的【找词闭环】。**

```
① 拿一份初始词根库（社群流传的 51 个经典词根扩展版，约 100 个）
        ↓                                    ↑
② 用词根批量查 Similarweb，下载 搜索量 > 3 万 / KD < 60 的词
        ↓                                    │
③ 另一条路：把每月的支付网关收入榜 / AI 工具收入榜的网址采下来
        ↓                                    │
④ 同样用 Similarweb 批量查这些站的词 —— 会发现两条路殊途同归
        ↓                                    │
⑤ 用能查 KD + 关键词解释（是什么 / 什么搜索意图 / 有什么商业价值）的工具，每天过 300 个
        ↓                                    │
⑥ 选当前最好的词，每两周做一个站，每站每天发 5 条外链
        ↓                                    │
⑦ 从做过的词里再提取新词根，更新词根库 ────────┘
```

**两条路会汇合，是这个闭环成立的证据**：词根扩出来的词和「已经在赚钱的站」排的词
大量重合，说明筛选标准抓到的是真需求，不是噪声。

## 三、信号源地图：往哪儿看

【经验】—— 多位答主，`bounty/fd0wrgx7fh`

按「**这个源告诉你什么**」分类，而不是按站点类型。每一类都有对应的取数脚本，
**具体用哪个脚本、要不要登录、有没有配额，全部在
[`../demand-sources.md`](../demand-sources.md)**——这里只给判断逻辑。

| 这个源回答的问题 | 典型源 | 信号的强度 |
|---|---|---|
| **谁已经收到钱了** | 支付网关引荐榜、应用商店付费榜、收入榜、独立开发者收入榜 | 最硬。钱已经流过去了 |
| **谁在花钱买流量** | 广告透明度中心、投放平台的热门素材库 | 很硬。持续投放 = ROI > 1 |
| **谁做了但没做好** | 各类差评区（应用商店、扩展商店、SaaS 点评站、社区吐槽帖） | 很硬。已验证市场 + 差执行 |
| **谁在为这件事付外包费** | 自由职业平台、二手交易平台的「代做」服务 | 很硬。需求具体到能标价 |
| **正在冒出来的新东西** | 新品榜、开源趋势榜、技术社区、AI 导航站的「最新」页 | 中等。曝光 ≠ 留存 |
| **持续涌现新词的平台** | 游戏数据库与聚合站、影视/资源站、新模型与新产品发布 | 中等偏强。新词 = 新需求 = 无老站霸占 |
| **用户的原话** | 社区许愿帖、视频评论区、内容平台下拉联想 | 中等。要配合搜索量验证 |
| **自己站上已经发生的浪费** | 自有 Search Console × 分析后台交叉 | 最高性价比。需求已确认存在 |
| **我自己在别人的产品里卡住的地方** | 亲身使用时的卡点：操作绕、功能缺失、价格不透明、导出麻烦、简单任务要反复手动 | 最弱。样本量 1，只能当线索起点——必须回到用户讨论、竞品差评、搜索结果里找到印证才算数 |

### 三条「怎么把源用透」的通则

1. **【经验】拿到一个好源，立刻用 AI 找同类源。** 直接问「推荐几个类似 X 的网站」，
   比自己想关键词去搜高效得多——很多时候你根本搜不到对的词。
   （`清仔`，`bounty/fd0wrgx7fh`）
2. **【经验】拿到一批同类站，不要一个个看，批量扒下来让 AI 做横向分析。**
   典型任务：「扒 100 个某品类的站，分析各自的付费功能」——
   **每一个付费点后面基本都映射着一个用户需求**。（`清仔`）
3. **【实测】把榜单站的 `sitemap.xml` 批量抓下来喂给 AI**，让它分析这些站都在做什么，
   再和自己站的功能做对比，找出自己缺的功能批量补上。
   某答主用这个方式把站点从日均约 100 次点击提到约 1000 次点击。
   **这条适合已有站快速发掘该上哪些内页，不适合从零选方向。**（`Dawn`，`bounty/fd0wrgx7fh`）
4. **【经验】两条证据分属不同类别才算互证，同一类里的两个平台不算。**
   上面那张表是按"这个源回答什么问题"分的类——先从"用户的原话"类挑一个源，再从"谁已经收到钱了"
   或"谁在为这件事付外包费"类挑一个源，最后用搜索结果那一类交叉验证，就够进下一步，
   **不必八类逛完**。反过来，三条线索全来自同一类源（哪怕分别在三个平台上）证明的仍然是同一件事，
   只能算一条。**不要因为某个平台上有一个帖子很热就直接开工**——那是一条线索，不是两类证据。
   这与 [`../playbooks/selection.md`](../playbooks/selection.md) §9"只有跨族命中才算交叉验证、
   同族内多店命中不算"是同一条原则在证据侧的说法。（独立开发者出海经验分享）

## 四、差评与「许愿句式」：用户原话就是页面标题

【经验】—— `金智` / `黄楚标` / `楓之随刃` / `日出东方`，`bounty/fd0wrgx7fh`

**差评是唯一由用户掏钱之后给出的反馈**，可信度远高于任何免费调研。
功能列表告诉你「他们做了什么」，差评告诉你「他们做了但没做好的」——后者才是机会。

### 4.1 差评矿脉分布

| 平台类型 | 适合研究什么 |
|---|---|
| SaaS 点评站（B2B 向） | 企业级 SaaS 的采购期望与落差 |
| 应用商店（移动端两家） | 付费意愿最明确的一批用户 |
| 浏览器扩展商店 | Micro SaaS / 工具站的直接对标 |
| 电商与建站平台的应用市场 | 垂直行业 SaaS 的现成需求清单 |
| 开源插件生态 | 技术用户的痛点，往往是「能用但难用」 |
| 泛社区与聊天社群 | 非结构化的真实吐槽，出现频次比单条内容重要 |

### 4.2 高价值差评关键句（直接当搜索/过滤词用）

```
Doesn't work with...      Please add...        Too expensive
Slow                      Stopped working      No longer works
Privacy                   Wish it could...     Need bulk...
```

**其中最值钱的一句是「I love this extension, but...」**——
前半句证明需求真实且用户已经投入，后半句就是切入点。

### 4.3 社区「许愿句式」

在搜索引擎里限定站点搜这些句式，命中的都是用户自己写下来的需求原话：

```
site:<社区域名> "is there a tool that" <领域词>
site:<社区域名> "I wish there was" <领域词>
site:<社区域名> "does anyone know a" <领域词>
site:<社区域名> "how do people make" <领域词>
```

延伸的**迁移类句式**同样高价值（这类用户需求已经明确，只是在换供应商）：
`alternative`、`replacement`、`migrate`、`too expensive`。

### 4.4 扩展商店的「已验证市场 + 差执行」信号

【经验】—— `金智`，`bounty/fd0wrgx7fh`。做 Micro SaaS / 工具站最值得挖的一条线。

**筛选形状：用户量很大，但评分不高。**

```
用户数 100K+ / 500K+ / 1M+   ×   评分 3.5 ~ 4.3
```

这个组合的含义是 **Validated Market + Bad Execution**——市场已经存在，产品执行不好。
然后去读评论区的那几句关键句（见 4.2）。

### 4.5 退款理由与「产品下线」

- **【实测】退款理由是最贵的信号**：它是用户掏钱之后主动要求拿回钱，
  给出的理由通常极其具体（有答主的一个退款理由是「找不到联系方式」）。
  样本量小不影响价值，因为它没有任何免费调研的表演成分。（`日出东方`）
- **【经验】关注大产品宣布关停**：几千万存量用户 + 官方迁移体验差
  = **数据迁移成为强时效刚需**。有案例是一个极简的导出扩展吃到近十万用户。
  监控形状：产品下线公告、扩展商店的下架/停更列表。（`清仔`）

### 4.6 拿到差评之后怎么读：三条纪律

【经验】—— 独立开发者出海经验分享（外部经验帖，未经本库实测）

4.1 回答的是"去哪儿挖差评"，这三条回答"挖到了怎么读"，每一条都会改变计数结果：

1. **不看星级看任务。** 有价值的不是他给了几星，是**他原本想完成什么、产品在哪一步没接住他**。
   读不出这两样的差评只是情绪，不进证据库——这与 4.2 那批关键句是同一个用法：
   那些句子之所以值钱，正因为它们后面跟着一个具体的任务。
2. **一条差评只是一个人的一次经历。** 判断偶发还是普遍，必须在别处找到同形状的抱怨，
   计数纪律见 [`../playbooks/selection.md`](../playbooks/selection.md) 闸门 2。
3. **差评会过期，必须亲自试用竞品复核。** 评论区里那条吐槽可能已经被修掉了，也可能官方早给了
   变通办法，而差评永远留在那里，日期还不一定显眼。**没有亲手走一遍竞品的对应流程，
   就不能把这条吐槽当成今天还存在的缺口**——这是差评矿最便宜、也最常被跳过的一步，
   跳过的代价是整个方向建立在一个已经被填上的坑上。

## 五、中文平台当探测器：国内卷得早，验证过的搬到英文市场

【实测】—— `袁锐钦` / `楓之随刃` / `Rhythmus`，`bounty/fd0wrgx7fh`

核心假设：**国内内容与交易平台的竞争密度高于英文市场，
在国内已经被验证过的需求，搬到英文市场往往还是一地垃圾站。**

| 平台形态 | 看什么 | 判据 |
|---|---|---|
| 内容平台的**搜索下拉联想** | 用户高频搜索的原话 | 联想词本身就是关键词 |
| 内容平台的**笔记数 vs 赞藏数** | 供给 vs 需求 | **内容少 + 赞藏高 = 最优机会**；评论区高频问「用什么工具」= 工具站需求 |
| 短视频平台**头部视频播放量** | 需求有没有流量 | 10w+ 且多条 = 有流量；评论区「求链接」「在哪买」= 变现信号；**有直播间在卖 = 商业闭环已跑通** |
| 二手交易平台（**最硬**） | 「想要」数 vs 商品数 | **想要多、商品少 = 供不应求**；有人卖 + 有成交 = 有人真掏钱。服务类需求（「XX 代做 5 元/张」）直接对应工具站机会 |
| **招聘 JD** 反推 | 多少公司在招同一类岗位 | 多家同时招 = 方向起量；**JD 里的高频词 = 行业正在用人力解决的问题** |
| 视频平台**评论区**（英文侧确认） | 中文验证过的词翻译后搜头部视频 | 有播放 = 英文有需求；评论里的「Is there a tool for...」= 需求在、供给缺 |

### 一个纯主观但很好用的信号：「就这？」

【经验】—— `Rhythmus`，`bounty/fd0wrgx7fh`

在推荐流平台上看到有人晒自己做的小工具，笔记流量大、点赞多、评论里感兴趣的人多，
**而你自己的第一反应是「就这？不就是 XXX 吗，我轻轻松松也能做」**——
那这个工具解决的问题大概率是个优质需求。

判据补充：骂的人少、说「求你别再做这个了」的少；说「这也太简单了吧」的人点进主页
看多半是写代码/重度用 AI 的人（**同行觉得简单 ≠ 用户觉得简单**）。

这个信号一次给齐四样东西：**需求具体、人群画像清晰、能推导定价、社媒营销策略也现成**。

## 六、延展法与「持续涌现新词的平台」

### 6.1 延展法：从一个已验证的原点向外扩

【实测】—— `李大山`，`bounty/fd0wrgx7fh`

和「词找站、站找词」共通，但方向不同：**先锁定一个已经被市场验证过的单点需求，
再沿着业务流程、场景、细分维度向外扩散**，梳理整条链路上现存的痛点。

原帖案例（AI 图像方向）：观察到「AI 职业头像」「AI 头发生成」这类工具已经拿到真实流量
→ 证明「生成人体局部图像」这个市场成立 → 以此为原点向外延展到人体其他部位
→ 衍生出一整串关键词与产品方向 → 顺着这条线找到了一个月访问量约 20 万的站。

**操作形状**：找到原点 → 沿场景/流程/细分维度做横向与纵向延展 → 批量得到衍生关键词。
任何行业都能套用。

### 6.2 研究任务的前一步和后一步

【经验】—— `Zhou.`，`bounty/fd0wrgx7fh`

一个工具完成了核心任务，**用户在这之前还要准备什么？之后还要导出、检查、分享什么？**
这些小环节往往竞争小得多，而用户已经在做了。

### 6.3 去持续涌现新词的平台捡新词

【经验】—— `清仔` / `峻菁`，`bounty/fd0wrgx7fh`

**新游戏就是新词，新词就是新需求。** 新品类持续上新的平台（游戏数据库、
游戏聚合站、独立游戏发布站、模型与新产品发布渠道）天然不断产出没有老站霸占的词，
**新手很适合从这里拿第一次正反馈。**

与之配套的验证动作（`峻菁`）：拿词去 SERP 首页看三件事——

1. 有没有站**用这个词做主域名**；
2. 有没有站**用这个词做内页**；
3. 这个词的 **KD** 是多少。

再叠一层时间维度：用自己积累的词库（哪怕是一张表格）看**某个词在过去 1–2 个月里，
搜索结果数量是不是在匀速递增**——递增说明这是个在起量的词，不是一次性热点。

## 七、自有站就是一座矿：GSC × 分析后台交叉

【实测】—— `日出东方` / `Dawn`，`bounty/fd0wrgx7fh`

**这一节性价比最高**：需求已经被确认存在（用户真的搜进来了），你只是在浪费它。

### 7.1 高曝光 + 高点击 + 低停留 = 已确认但没被满足的需求

只看流量是浪费。把 Search Console 的「搜索词 → 落地页」和分析后台的
「停留时长 + 跳出率」拼起来看，找 **高曝光 + 高点击 + 低停留** 的组合：

> 这类词含义很明确：用户带着明确期待搜进来了，我没给到他要的东西。
> 不是需求不够，是需求已经被确认存在，而我正在浪费它。

实操：导 28 天「查询–页面」数据 → 导页面停留时长 → 按落地页 join
→ 筛 **点击 > 10 且停留 < 30 秒** → 逐个看这些搜索词到底在问什么。

原作者用这张表挖出过一个工具，现在每周两百多人在用免费功能，
并且明说「这张表里肯定还躺着好几个没做的」。

### 7.2 直接让 AI 过一遍 GSC 全部搜索词

找哪些需求没被满足，然后深入调研并实现。这条和 7.1 是同一个矿的粗筛与精筛。（`Dawn`）

### 7.3 竞品的「付费墙位置」逆向法

【经验】—— `日出东方`，`bounty/fd0wrgx7fh`

竞品数据库里记支付平台、定价、免费额度、Upsell 都是表面。
**真正的信息是：竞品把付费墙放在哪一步。**
付费墙的位置是竞品用真金白银试出来的「用户愿意掏钱的那个瞬间」——
**他们已经替你做完了 A/B 测试，答案就明晃晃写在页面上。**

| 付费墙位置 | 说明什么值钱 |
|---|---|
| 输入信息后立刻收 | 「生成结果」这个动作本身值钱 |
| 给了摘要之后才收 | 「完整性」值钱 |
| 第二次访问才收 | 「持续性」值钱 |
| 只在某个特定问题上收 | **那个问题最痛** |

反向自查：如果你的免费功能有人用、却一个都不付钱，
很可能是**免费部分给多了，用户在走到付费墙之前就已经满足了**。

## 八、判断一个需求值不值得做：六条认知与三个公式

前五条：【经验】—— `我话事`，`bounty/fd0wrgx7fh`。作者自述「每一条都是真金白银和时间换的」。
第六条来源不同，是本 Skill 侧的实测，单独标注。

1. **伟大的技术，原始的需求。** AI 迭代很快，但人对工具的需求迭代很慢。
   Web 时代、移动时代就存在的产品，今天用 AI 重做一遍照样赚钱。
2. **大模型能实现，不代表用户会用大模型。** 「批量生成公众号文章」豆包/DeepSeek 都能做，
   但对应的独立 App 依然一堆。不要陷入「大模型有了我就没得赚」的误区。
3. **先有用户，再开发。** 写第一行代码之前先做一个页面，假装产品已经存在，然后：
   - 拿这个 demo 去分发，看一个月内能不能拿到几百上千个用户；
   - 页面上写「**立即购买**」而不是「立即预约」——预约测不出付费意愿；
   - 不要开发完整功能，先让用户付钱、**手搓交付**。

   进阶用法：同一个方向做几个不同的 demo 页面分别分发，**哪个功能点吸引到注意力就开发哪个**。
4. **便宜是一个坏生意。** 除非是视频/图片生成这类按量计费，否则尽量包装成按月或按年
   订阅的固定价格，**不要卖积分**——卖积分吸引来的全是价格敏感型用户。
   卖不出去时第一反应不是降价，而是「我没给用户一个愿意多付钱的理由」。
5. **一个很烂的产品都有人付费和夸奖，说明这个需求真的很痛。** 看到粗糙、不稳定却有人夸的
   产品，不要嘲笑它，要敬畏它——那是需求强度的直接证据。

### 第六条：能排上去 ≠ 能赚钱，这两件事要分开验

【实测 2026-08-28】上面五条讲的是需求强度，这一条讲的是**需求强度与可得收入之间的落差**。

一条赛道可以同时满足：低难度档一百多个词、几十万月搜、加权 CPC 接近 $1、
二十多个独立新站十五个月内进场拿到首页（最新的域龄两个月）——**所有选词指标全绿**。
而同类站的真实流量只有几百到八千/月，折成展示广告是每月二十到一百美元。

两条判据：

1. **进入门槛低是坏消息，不是好消息。** 两个月能进去，说明没有护城河；
   新进入者时间线在加速（每半年新域数量递增）时，你在的是淘金潮末段，不是开端。
2. **搜索量不是流量，流量不是收入。** 这两次折损都可以是一个数量级，
   而它们会被「KD 低 + 有新站在排」这个漂亮的组合完全遮住。
3. **【经验】这条落差是双向的，只防一边会漏掉另一边。** 「看起来用户很多」和「能赚到钱」之间
   没有必然对应，反过来同样成立——**冷清、月量很小的方向可能付费率极高**
   （[`../playbooks/selection.md`](../playbooks/selection.md) 闸门 3 那条"一百多个带预算的人
   比三万多个找免费模板的人值钱"就是这一侧的实例）。只防前一个方向，会把一批低流量高付费的
   方向当「量太少」误杀——这正是 [`../playbooks/research.md`](../playbooks/research.md)
   「否决前必须反查」那张安全网要挂在**所有**否决理由上、而不是只挂在「量太少」上的原因。
   （独立开发者出海经验分享）

操作上：**选词调研跑完量、难度、窗口三项之后不要下裁决**，
先去查同类站的真实流量（面板口径）并折成钱，再决定做不做。
**怎么取那份流量数**（provider 选择、Similarweb 与 Semrush 的口径差、
拿不到流量结构时退到哪里补）见 [`demand-sources.md`](../demand-sources.md)
「⓪ 这一步的供应商选择」与「②·六·四 Semrush 的自然流量什么时候不能信」两节；
那边「十·五」只留一条「第四道闸」的操作规则，判据仍以本节为准。

#### CPC 怎么读（脚本：`demand/keyword-value.mjs`）

【实测 2026-08-28】CPC 在四个解析器里都抓下来了，但**全库没有一个决策脚本读过它**，
判断规则散在三处从没落成可执行的东西。现在收敛到一个入口：

```bash
node rankup/scripts/demand/keyword-value.mjs --in <关键词 JSON/JSONL>
```

它吃 `semrush-report --report keyword-magic`、`semrush-keyword` 的 `--out`，
以及任何 `[{keyword, volume, kd, cpc}]`。要点三条：

1. **CPC 是 U 型，不是越高越好。** 太低说明广告主不愿为这个词付钱；太高说明你在跟
   买量的公司抢，此时 KD 不可信（见本文件外的 [`seo-growth.md`](../seo-growth.md)
   负向清单）。**「太低」「太高」这两句判断在文档里，不在脚本里**——脚本只给
   `cpc` 和 `ratioToMedian`（这个词的 CPC ÷ 这批词的中位数）这两个数，
   比值明显偏高的词值不值得先查一次 SERP，是你看着这批词的分布决定的。
2. **参照系是这批词自己的中位数，不是绝对金额，而且只给比值、不给档位名。**
   实测 image converter 这个工具赛道 100 个词的 CPC 挤在 $0.9–1.1，而保险、
   法律类单词能到几十美元——一套写死的阈值套所有垂类，是用一个凭空的数字覆盖
   真实分布。2026-08-30 重构第二波连 `low/normal/high` 这三个档位名也删了
   （脚本里已无 `level` 字段）：「远低/正常/远高」同样是判断，而一个档位名一旦
   出现在输出里，就会被当成测量结论抄进报告。
3. **`cpc: null` 不等于 `cpc: 0`。** 前者是这次没读到，后者是广告主明确不出价。
   把前者当后者，就是把一次抓取失败读成了业务结论。

它的收入估算只给区间并强制附带假设，因为「选词指标 → 真实收入」目前**只有一个
实测锚点**（就是上面第六条那条赛道），样本量 1。能支撑的结论只有本条第 2 点那句
「两次折损各一个数量级」。

实测校验：拿 `image converter` 那批 100 个词跑出来是 **$20.55–255.65/月**，
和第六条案例实测的 $20–100/月落在同一量级——两条独立路径互相印证。
而这批词里的主词月搜 18,100、KD 69，单看月收入区间是 **$4.5–57**。

### 第七条：需求成不成立，和自己接不接得住，是两道分开的自查

【经验】—— 独立开发者出海经验分享（外部经验帖，未经本库实测）

前六条判的都是需求本身。这一条判的是「换成我来做，成不成」，两道自查都在写第一行代码之前做完：

1. **最低限度的功能对齐——基线由竞品定，不由自己拍。** 打开首页排名靠前的两三个产品，
   **亲自走一遍它们的核心流程**（用户从哪进来、怎么完成任务、最后拿到什么结果），拆成几个基础
   功能，然后问一句：第一版能不能至少把同样的核心任务完成掉？答不上来，说明还没看清要对齐的是
   什么——那不叫「我们做减法」，叫没量过基线。「最小但完整」里的完整怎么理解，见
   [`zero-to-one.md`](zero-to-one.md) 二·第二关；这道自查同时是那条「只看竞品有哪些功能」反模式的
   补充：功能列表要用走流程的方式读，不是照着勾选框抄。
2. **接不接得住这批用户。** 能不能做出不输给竞品的基础体验、能不能理解这批人在什么处境下用它、
   愿不愿意长期处理他们的客服与反馈。**有些方向看起来有钱，但自己既没有能力也没有兴趣长期服务
   这批人。** 这不是硬约束意义上的出局（结构性的那几条在
   [`../playbooks/selection.md`](../playbooks/selection.md) 闸门 0），而是一条要等到上线几个月后
   才发作的慢性否决——它不会让方向在闸门上变红，只会让人在需要打磨的那一段悄悄停下来。

### 三个可以直接拿来打分的公式

【经验】—— `金智` / `黄楚标` / `Zhou.`，`bounty/fd0wrgx7fh`。
三条是同一件事的三种粒度，**从粗到细依次用**。

```
① 选赛道：  成熟市场 × 已验证需求 × 明确痛点 × 某个细分人群 × 可以明显改善
② 排优先级：需求价值 ≈ 痛苦程度 × 发生频率 × 付费能力 × 当前解决成本
③ 过门槛：  有人反复做 + 现在很麻烦 + 已经有人付钱 = 值得验证
```

公式 ① 是**连乘**，所以任何一项为零整个方向就为零——
「成熟市场」缺席就是在教育市场，「细分人群」缺席就是在和巨头正面打。

公式 ② 里最容易被低估的是**当前解决成本**：用户现在用二十步教程 + 三个工具拼出来的结果，
本身就是你的定价空间。

### 八个可以直接扫的「需求形状」

【经验】—— `黄楚标`，`bounty/fd0wrgx7fh`。每一条都是一个可以做成监控的检索式。

| # | 形状 | 怎么扫 |
|---|---|---|
| 1 | **低评分** | 专门找 1–3 星评论，提取「为什么不好用」 |
| 2 | **代做服务** | 自由职业平台、二手平台上别人已经付钱让人解决的问题 |
| 3 | **招聘 JD** | 大量招同一个重复岗位 = 企业正在用人工解决的问题 |
| 4 | **超长教程** | 一件事要 20–30 步才能完成 = 很可能可以产品化 |
| 5 | **Excel 黑洞** | 复杂、重复、每周手工维护的表格 = 半成品 SaaS |
| 6 | **工具拼接** | 用户同时用三四个工具才能完成一件事 = 一体化机会 |
| 7 | **迁移需求** | 搜 `alternative` / `replacement` / `migrate` / `too expensive`，这类用户需求已明确 |
| 8 | **异常价格** | 看似简单的工具却有人付 $20/$50/$100 每月 = 背后解决的是商业流程 |

### 关于「抄」的边界

【实测】—— `祥子`，`bounty/fd0wrgx7fh`

原帖直白地写「大佬站直接抄」，并给出自己借鉴后做到约 1000 美元收入的结果。
**但作者自己给了边界，这个边界必须一起记**：

> 这里说的「抄」，不是原封不动复制代码、品牌和内容，而是**拆解对方已经验证过的
> 关键词、用户需求、页面框架、定价策略、转化路径与外链渠道**，再结合自己的产品重新设计。

可拆解的六件事：首页结构、功能内页、关键词布局、站内互链、流量入口、商业化方式。
遇到成熟站群时，**逐个站拆而不是只拆主站**——站群的价值在于它展示了同一套打法
在多少个细分方向上被复用过。

**红线**：复制代码、品牌资产、正文内容是侵权，不是方法论。

### 先有用户再开发的进阶：把「先有用户」也自动化

【经验】—— `前行`，`bounty/fd0wrgx7fh`

两条互补的入口：

1. **从自己原来的行业入手。** 跨界做工具站的人，最快跑通冷启动的往往不是找到最好的词，
   而是**把自己本行业每天在做的重复、枯燥、麻烦的事做成产品，先卖给同行朋友**。
   这条路径把「验证需求」和「拿到第一批付费用户」合并成了一步。
2. **把「每天看已验证产品」交给定时任务。** 让聊天式 AI 每天推荐几个已被市场验证的产品，
   每个都分析好评、差评、可切入的细分方向、可做的关键词与长尾词，
   拿到词之后再走常规的关键词验证流程。

## 九、这一章的反模式

| 反模式 | 为什么错 | 正确动作 |
|---|---|---|
| 从「我觉得这个很酷」开始选方向 | 方向错了，代码写得再漂亮也是自嗨 | 让数据替你选词，不要让自己替数据选词（`bounty/fpswv8z126`，`阿鲁巴`） |
| 上线三个月没流量没付费，第一反应是「推广还不够」 | 这个归因把问题推到了链路最后一环，于是接下来做的是加渠道、堆功能、改按钮，而真正没做过的是最初那三个确认：谁会用、他为什么现在就要用、他会去哪里找解决办法 | 先回到需求证据与「这个问题有没有被用户用搜索表达出来」重判一次方向，再谈推广；判据见 [`../playbooks/selection.md`](../playbooks/selection.md) 闸门 1–3（【经验】，独立开发者出海经验分享） |
| 反推对标站时，把「看起来成功」当「真的成功」 | 新人最常掉的坑：对标了一个其实没拿到结果的站 | 先验证它真的拿到了结果——流量结构、非品牌词占比、付费页引荐（`bounty/fpswv8z126`，`王焱`） |
| 看到宽泛大词就开做 | 「AI 换脸」和「AI 换脸在线工具免费」背后是完全不同的人 | 把词按意图分层（宽泛 / 了解信息 / 找方法 / 找产品 / 找免费体验），只做接近决策的那层（`bounty/il1fmki1ih`，`我话事`） |
| 在选词上无限纠结，迟迟不上线 | 找词重要，但对新手而言产品、流量、转化能力都还没有，纠结出的完美词也吃不下 | 找一个中等难度的红海词先练手，把整条流程跑通（`bounty/fpswv8z126`，`Angler`） |
| 知道一堆方法，但每个只执行三五次就放弃 | **本章最大的坑**。不起量就没有结果，而人对枯燥动作的耐受度极低 | 把已知方法交给 agent 跑量，人只负责调筛选规则（`bounty/fd0wrgx7fh`，`程序员卡诺`） |
| 把「工具面板给的收入/下载量」当财务数字用 | 【实测】具体数值不准，只有趋势和量级是对的 | 只用于排序和量级判断，不进任何测算（`bounty/fd0wrgx7fh`，`我话事`） |
| 只看竞品「有哪些功能」 | 功能列表是他们做了什么，差评和付费墙位置才是他们验证出了什么 | 差评看缺口，付费墙位置看付费瞬间（`bounty/fd0wrgx7fh`，`日出东方`） |
| 词根库全是英文 | 中国人搜「JSON 编辑器」不搜「JSON editor」，多语言词根是一整片没人挖的矿 | 词根 × 语言做乘法，量太大就交给 agent（`bounty/fd0wrgx7fh`，`程序员卡诺`） |
| 看到被社区折叠/低分的回答就跳过 | 该帖 17 条被折叠的回答里有本章最可执行的几条方法 | 折叠是投票结果，不是质量判定；自己读一遍再决定 |

关于「怎么把挖到的方向收敛成可做的词」，见 [`../trends.md`](../trends.md) 与
[`../seo-webcafe.md`](../seo-webcafe.md)；关于「这个词难不难做」，用
`scripts/seo-webcafe.mjs kd`。
