# 经验库（experiences/）

**这里存放「别人用真金白银换来的裁定」——不是官方文档，不是我们自己的项目事实。**

规划一个新站、做前期调研、决定下一轮迭代改什么的时候，先来这里翻一遍。
这些条目回答的都是同一类问题：**「这一步该怎么做，别人已经踩过哪个坑」**。

> **历史效力（2026-10-03）**：本目录的旧选词阈值、评分、量筛与经营公式保留作来源经验，不是当前选词与立项的判据唯一源；当前流程与裁决见 [entry.md](../playbooks/entry.md#选词判据只看两个)，具体被取代部分见各文件头部提示。

## 三层归属：什么写在哪里

| 层 | 位置 | 放什么 | 判据 |
|---|---|---|---|
| 方法层 | `references/*.md`（本目录之外） | 我们自己的工作流、脚本用法、平台接入 SOP、技术规则 | 「怎么操作」 |
| **经验层** | **`references/experiences/*.md`（本目录）** | **从业者验证过的判断与裁定，含出处与证据等级** | **「该怎么判断、别人踩过什么坑」** |
| 项目层 | `<project>/.rankup/experience.md` | 本站验证过的结论、真实数字、证据出处 | 「我们这个站上发生了什么」 |

这张表只讲 Skill 内部（方法层、经验层）与项目层的分工；只对某个用户或某台机器成立的经验进用户全局层 `~/.rankup/`，不属于 rankup 链路的归别的 Skill，判定见 [`../maintenance.md`「七」](../maintenance.md#七经验分层与回流四层归属唯一判定表)。

**边界是硬的**：经验层不带任何站名、域名、流量数字、账号 ID、本机路径。
一条经验如果剥离站点后就不成立，它属于项目层，不属于这里。

## 收录规则（强制）

新增或修订经验条目时逐条对照：

| 规则 | 为什么 | 反面教材 |
|---|---|---|
| **只收能改变下一步动作的** | 「要重视用户体验」这类话不构成裁定，收进来只会稀释真正有用的条目 | 把一整篇帖子原样搬进来 |
| **必须写出处**（URL 路径 + 作者名） | 后来的人要能回溯原文判断适用边界；无出处的条目无法验证也无法证伪 | 「听说注册率能提升 50%」 |
| **必须标证据等级** | 实操数据和个人猜测混在一起，读的人只能全盘照抄或全盘不信 | 把作者明确标注为「猜测」的内容写成结论 |
| **与我们已有规则冲突时，写出冲突并给裁定** | 沉默的冲突会让下一次执行随机选一边 | 收录「别用 Cloudflare」却不提本 Skill 默认 CF-first |
| **灰度手法必须标灰度，并给出我们的取舍** | 有些手法有效但违反合规或我们的原则，不标注就等于默认采纳 | 把「假等待」当成中性技巧收录 |
| **同一主题合并进既有文件，不新建文件** | 一个主题散在三个文件里，等于三份都不完整 | 每读一个帖子建一个新文件 |
| **被推翻时修订原条目，不并列** | 并列两个冲突结论 = 把判断成本推给下一次执行 | 在文件末尾追加「补充：其实上面那条不对」 |

### 证据等级标记

条目里用这三个标记，写在结论前面：

- **【实测】** —— 作者给出了自己的数据、金额或对照组。
- **【经验】** —— 作者的从业判断，没有附数字，但描述了具体场景。
- **【猜测】** —— 作者自己标注为推测，或明显没有验证路径。**不得当作结论执行**，只能当作待验证假设。

## 来源与适用边界

本目录当前条目来自 `new.web.cafe` 的经验帖（`/experience/<id>`）与悬赏问答
（`/ask/bounty/<id>`）。这些是中文出海独立开发者社群的从业者答案，**不是搜索引擎
或平台的官方文档**：

- 多数结论来自单一站点的单次实践，样本量为 1，且各人的流量结构差异很大。
- 悬赏帖的排序是**投票结果**，反映的是社群共识度，不是正确性。被折叠的回答不一定错，
  高分的回答也不一定适用于我们。
- 采纳任何一条之前，先问「我们这个站的前提条件和它一样吗」，并按小步验证执行——
  验证结果（成立或不成立）写回项目的 `.rankup/experience.md`，不要改这里的原始裁定。
